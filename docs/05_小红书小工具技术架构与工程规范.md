## 一、工程定义

《苏轼宇宙》V1 比赛版采用：

> **离线 H5 MiniTool 静态 ZIP 包。**

核心目标：

> **轻量、稳定、自包含、低端兼容、可审计、可交付。**

正式运行不依赖服务器、数据库、CDN 或任何网络请求。

```text
打开 index.html
→ 本地加载数据/素材
→ 本地完成测试计算
→ 本地展示结果与人生宇宙
→ 本地生成 Canvas 分享卡
→ 仅在保存/发布阶段调用 window.xhs.miniTool.*
```

## 三、正式技术栈

V1 推荐并默认采用：

```text
HTML5
CSS
Vanilla JavaScript（ES2017）
JSON
SVG
Canvas 2D
window.xhs.miniTool Native Bridge
```

### 3.1 默认不采用

- React / Vue 等大型运行时；
- Next.js；
- ES Module runtime；
- WebGL 作为核心视觉依赖；
- 大型 polyfill；
- 第三方在线 SDK；
- 远程 API。

若未来确需引入框架或构建工具，必须同时证明：

1. 最终产物完全符合 CSP；
2. 最终 JS 已转译到 ES2017 / Chrome 61；
3. 不残留 `type="module"` / import/export；
4. 包体与审计通过；
5. 引入收益明显高于原生实现。

## 五、CSP 与脚本规范

### 5.1 Classic Script

正式页面只使用：

```html
<script src="./js/namespace.js"></script>
<script src="./js/app.js"></script>
```

禁止：

```text
<script type="module">
import
export
eval()
new Function()
WebAssembly
iframe
object
```

### 5.2 禁止内联 JS

禁止：

```html
<script>...</script>
<button onclick="...">
<a href="javascript:...">
```

事件统一使用 `addEventListener`。

### 5.3 命名空间

多文件推荐：

```js
window.SuShiUniverse = window.SuShiUniverse || {};
```

子模块挂载到统一命名空间，避免无节制污染全局变量。

## 六、JavaScript 兼容基线

目标环境：

> **Android 8.1 / Chrome(WebView) 61 / ES2017。**

直接运行代码不得依赖未转译的 ES2018+ 语法。

尤其禁止裸用：

```text
?.
??
```

以及其他超过基线、未经兼容验证的语法或内建 API。

原则：

- 优先直接写 ES2017；
- 避免复杂转译链；
- 不引入全局大 polyfill；
- 必需新能力采用局部兼容函数。

---

## 七、CSS 兼容与设计系统

### 7.1 基线原则

> **先保证 Chrome 61 可用，再做现代浏览器增强。**

不得将以下能力作为唯一布局实现：

- Flex `gap`；
- `aspect-ratio`；
- `clamp()`；
- CSS 逻辑属性；
- `:has()`。

Flex gap 如需增强，必须采用 Skill 要求的真实 DOM 行为检测，而不是只写 `@supports (gap: 1px)`。

### 7.2 Design Tokens

集中维护：

```text
颜色
字号
行高
间距
圆角
边框
阴影
动效
z-index
safe-area
```

页面不得各自发明一套视觉常量。

## 八、跨端与安全区

### 8.1 事件

交互优先 Pointer Events：

```text
pointerdown
pointermove
pointerup
```

减少鼠标与触摸两套逻辑分叉。

### 8.2 安全区

统一使用双兼容写法：

```css
padding-top: var(--safe-area-inset-top, env(safe-area-inset-top, 0px));
padding-right: var(--safe-area-inset-right, env(safe-area-inset-right, 0px));
padding-bottom: var(--safe-area-inset-bottom, env(safe-area-inset-bottom, 0px));
padding-left: var(--safe-area-inset-left, env(safe-area-inset-left, 0px));
```

必须同时验证 PC 模拟器与真机 WebView。

## 十三、分享卡标准链路

正式路线：

```text
Result/Daily/Station 数据
→ ShareCardViewModel
→ Canvas 2D
→ data URI / 图片数据
→ writeTempFile（需要时）
→ filePath
→ saveImageToPhotosAlbum / postNote
```

禁止：

- 页面截图作为唯一方案；
- 远程截图服务；
- 网络上传换 URL；
- `<a download>`；
- 自动发笔记。

Base64 只用于短生命周期的桥接；单条解码 >100 KiB 触发警觉，>1 MiB 必须拆为独立资源/优化流程。

## 十四、视觉与资源工程

V1 视觉实施顺序：

```text
CSS
→ SVG
→ Canvas 2D
→ 少量压缩 WebP
```

优先程序化实现：

- 夜色渐变；
- 月光；
- 星点；
- 江水/水纹；
- 雾层；
- 人生线路。

系统字体优先，不把大字体包作为“古风感”来源。

V1 默认不使用 WebGL。若未来启用，必须独立任务实现性能预算、掉帧降级、context lost 恢复和 Canvas/静态兜底。

## 十五、性能预算

### 15.1 ZIP

```text
推荐目标：≤ 2 MiB
硬上限：≤ 10 MiB
```

本项目将 ≤2 MiB 作为正式优化目标；超过 2 MiB 必须在成果说明解释主要资源来源与继续优化空间。

超过 10 MiB 直接判定 P0 阻塞。

### 15.2 文本

- 单文本文件 >2 MiB：警告；
- 解压文本总计 >5 MiB：警告。

### 15.3 Canvas / 动效

- 控制 DPR；
- 动画不可见时停止；
- 重复生成分享卡后释放大 Canvas/图片引用；
- 禁止大量永久粒子；
- 低端机稳定优先。
