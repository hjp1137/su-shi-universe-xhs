## 一、设计目标

本项目的交互目标不是“把苏轼资料放进手机”，而是让用户在 30—90 秒内完成一次完整体验：

```text
我最近怎么了
→ 苏轼也走过类似的风雨
→ 我读到一句真正属于他的诗文
→ 我获得一个不过度说教的理解
→ 我愿意做一件很小的事
→ 我愿意保存/分享这张卡
```

所有页面都服务于三件事：

1. **快速进入**：用户不需要先学习怎么用；
2. **情绪连接**：先从用户当下出发，再进入苏轼；
3. **形成闭环**：测试、阅读、行动、分享必须连续完成。

## 二、V1 信息架构

```text
首页 Home
├── 主入口：测一测｜你的人生正在东坡哪一站
├── 高频入口：坐一会｜今日东坡
├── 探索入口：逛一逛｜苏轼人生宇宙
└── 最近结果（本地可用时显示）

测试 Quiz
├── 测试说明
├── Q1—Q8 单题页面
└── 计算结果

结果 Result
├── 结果揭晓
├── 苏轼当时发生了什么
├── 对应作品 / 诗句
├── 东坡式理解
├── 今日小行动
├── 查看人生站点
└── 生成分享卡

宇宙 Universe
├── 人生生命线
├── 九大人生站点
└── 站点详情 Station

今日东坡 Daily
├── 今日诗句
├── 真实背景
├── 东坡式理解
├── 今日小行动
└── 生成今日东坡签

分享卡 Share Card
├── 预览
├── 保存/发布能力
└── 返回结果/再次测试
```

V1 不增加独立“作品大全”“人物百科”“搜索页”“社区页”。

## 三、全局导航原则

小工具不是传统网站，不建议使用复杂底部五栏导航。

V1 推荐采用：

- 首页承担总入口；
- 内容页顶部提供轻量返回；
- 结果页提供“继续逛苏轼宇宙”；
- 宇宙页提供“回到首页 / 今日东坡”；
- 分享卡完成后提供“重新测一次”。

必须避免用户进入深层页面后找不到返回路径。

## 四、首页设计

### 4.1 首页任务

首页只解决三个问题：

```text
这是什么？
我现在可以做什么？
为什么值得点进去？
```

### 4.2 第一屏结构

建议第一屏控制在一个手机屏幕内：

```text
[月 / 江 / 远山的主视觉]

苏轼宇宙

遇到烦心事，
先去东坡那里坐一会儿。

[ 看看我的人生正在东坡哪一站 ]

今日东坡
“……”
[坐一会]
```

第一屏禁止：

- 大段苏轼简介；
- 多个并列一级按钮；
- 九个站点全部露出；
- 大量作品封面；
- “AI”“知识图谱”等技术词抢占用户注意力。

### 4.3 第二屏入口

三张轻卡：

1. **测一测**｜你的人生正在东坡哪一站？
2. **逛一逛**｜从眉山走到天涯
3. **坐一会**｜今日东坡

其中“测一测”视觉优先级最高。

### 4.4 首页滚动节奏

推荐：

```text
主视觉
↓
三大入口
↓
一句“为什么是苏轼”
↓
人生宇宙局部预览
↓
底部品牌署名
```

整个首页应短，不做门户站。

## 五、测试流程设计

### 5.1 开始页

开始前只说明：

> 用几道生活化的小问题，看看你最近更像苏轼人生中的哪一站。

补充一行边界说明：

> 这是文学互动体验，不是心理测评。

按钮：

> **开始走一程**

### 5.2 单题布局

每题单屏或近似单屏：

```text
3 / 7
────────

最近最让你费心的是什么？

[事情很多，脑子停不下来]
[努力了，但结果总不如预期]
[太在意别人怎么看我]
[没什么大事，就是有点累]

            [下一题]
```

优先支持“点击选项后自动进入下一题”或短暂轻反馈后进入下一题。

### 5.3 进度表达

只显示简单进度：

```text
3 / 7
```

或细线进度条，不做游戏化积分、等级、倒计时。

### 5.4 选项文案原则

- 每个选项只表达一个主要状态；
- 长度尽量接近；
- 不使用“严重焦虑”“抑郁”“人格缺陷”等词；
- 不设计明显“正确答案”；
- 避免用户觉得自己被审判。

### 5.5 返回与重选

允许返回上一题修改答案。

不得因为误触导致用户必须从头开始。

## 六、结果页设计

结果页是整个产品的核心页面。

### 6.1 首屏：先揭晓，不先解释

```text
你的苏轼人生站点

黄州｜重新生活

你最近可能不是走不动了，
只是走到了需要换一种节奏的地方。

[慢一点] [重新生活] [继续往前]
```

用户第一眼必须知道“我得到什么结果”。

### 6.2 第二段：真实的人生

标题示例：

> **那时候，苏轼也刚刚经历一场大风雨。**

内容必须来自审核后的 `fact_summary` / `summary_story`。

控制为 2—4 个短段落，不做传记长文。

### 6.3 第三段：真正属于苏轼的文字

诗句视觉上独立：

```text
“莫听穿林打叶声，
何妨吟啸且徐行。”

——《定风波·莫听穿林打叶声》
```

原文与产品解读之间要有明显视觉间距。

### 6.4 第四段：东坡式理解

标题可用：

> **如果把这句话放回今天**

而不是：

> 苏轼告诉你

这样可以明确现代解读边界。

### 6.5 第五段：今日小行动

以独立卡片呈现：

```text
今天只做一件小事

把一件今天解决不了、
却一直在脑海里打转的事先放下，
出去走十分钟。

[我去走走]
```

点击后只做轻反馈，例如：

> “好，今天先走到这里。”

不做强打卡压力。

### 6.6 第六段：分享

主按钮：

> **生成我的东坡人生卡**

次按钮：

> 看看苏轼的这一站

底部弱按钮：

> 重新测一次

## 七、苏轼人生宇宙页

### 7.1 目标

宇宙页不是百科目录，而是让用户产生：

> **“原来苏轼这一生走了这么远。”**

的整体感受。

### 7.2 页面骨架

```text
苏轼宇宙
从眉山，到天涯，再回来。

[江河式纵向生命线]

○ 眉山｜少年出发
│
● 京师｜一举成名
│
○ 密州｜人到中年
│
● 乌台｜人生骤雨
│
★ 黄州｜重新生活
│
○ 杭州｜把日子过好
│
○ 惠州｜岭南烟火
│
○ 儋州｜天涯仍有书声
│
○ 常州｜归途与谢幕
```

当前用户测试命中的站点可高亮，但不能因此隐藏其他站点。

### 7.3 节点交互

点击节点：

- 节点轻微放大；
- 展开一句摘要；
- 显示 1—3 个代表作品；
- 提供“进入这一站”。

不建议在生命线上直接放大段文字。

### 7.4 滚动行为

首次从结果页进入宇宙页时，可自动定位到当前站点，但必须允许用户自由上下浏览。

## 八、站点详情页

每个站点统一结构：

```text
站点名 + 主题
↓
时间 / 地点 / 年龄（经审核）
↓
一段真实故事
↓
代表作品 2—4 项
↓
代表诗句
↓
东坡怎么过这一关
↓
今天可以怎样理解
↓
今日小行动
↓
上一站 / 下一站
```

站点详情不重复测试结果页的完整文案，应提供更多人物与作品内容。

## 九、“今日东坡”设计

### 9.1 定位

这是用户第二次以后最值得重复打开的入口。

不是签到，不要求连续天数。

### 9.2 页面结构

```text
今天是一个普通日子。
东坡给你留了一句话。

[诗句]

这句话写在怎样的人生里
[真实背景]

放到今天
[东坡式理解]

今天的小事
[行动建议]

[生成今日东坡签]
```

### 9.3 每日策略

V1 使用本地日期映射静态内容：

```text
dayKey = 本地日期
index = stableHash(dayKey) % approvedDailyItems.length
```

同一天多次进入尽量看到同一条，形成“今日”感。

## 十、分享卡交互

### 10.1 三类卡片

1. **人生站点卡**
2. **今日东坡签**
3. **人生节点收藏卡**

### 10.2 卡片预览页

用户必须先看到实际卡片预览，再触发保存或发布。

页面结构：

```text
[完整卡片预览]

[保存/发布]
[换一个版式]（V1 可选）

重新测试 | 返回
```

### 10.3 卡片信息优先级

人生站点卡固定：

```text
1. 结果名称
2. 关键词
3. 一句真实诗文
4. 一句产品解读
5. 苏轼宇宙品牌
6. 引导语：你的人生正在东坡哪一站？
```

不要把长历史背景塞进分享卡。

## 十一、状态与反馈

### 11.1 加载状态

由于 V1 核心数据本地化，正常页面不应出现长时间 Loading。

图片或卡片渲染需要等待时：

> 正在把这一程收进卡片里……

### 11.2 空状态

如本地数据异常：

> 这一页暂时被江雾遮住了。

提供：

> 回到首页

但工程日志必须记录真实错误，不能只用文艺文案掩盖故障。

### 11.3 错误状态

面向用户：简短、可恢复。

面向开发：保留错误码、数据 ID 和上下文。

---

## 十二、动效交互规范

### 12.1 允许

- 雾气缓慢漂移；
- 月光轻微位移；
- 江面轻微波纹；
- 节点呼吸；
- 结果页内容分段淡入；
- 分享卡生成时的纸张成形感。

### 12.2 禁止

- 高频闪烁；
- 自动连续震动；
- 强制长动画；
- 影响文字阅读的粒子层；
- 每次点击都触发复杂转场；
- 不能跳过的片头动画。

### 12.3 时长建议

多数反馈 120—300ms；
氛围动效可持续但必须低频、低干扰。

---

## 十三、移动端可用性

- 主要按钮点击区域足够大；
- 正文不使用过小字号；
- 关键信息不要只靠颜色区分；
- 长诗文必须合理换行；
- 分享卡中的诗词必须在小屏预览中仍可辨认；
- 首屏核心 CTA 不应被机型安全区遮挡；
- 不依赖 hover；
- 所有关键流程可单手完成。

---

## 十四、文案层级

建议统一：

### H1

页面唯一核心标题，例如：

> 黄州｜重新生活

### H2

叙事问题，例如：

> 那时候，苏轼发生了什么？

### H3 / 卡片标题

生活化提示，例如：

> 今天只做一件小事

### 正文

短段落、少长句。

### 标签

最多 3 个核心关键词，避免标签墙。

## 十五、埋点建议

即使比赛 V1 暂无正式后端，也建议在代码中统一事件名，为后续数据验证预留：

```text
home_view
quiz_start
quiz_answer
quiz_complete
result_view
station_open
universe_view
daily_view
action_click
share_card_generate
share_card_save
share_card_publish
quiz_restart
```

如果平台当前能力不支持远程埋点，则先实现本地事件封装接口，不以网络依赖阻塞 V1。

## 十六、核心用户路径验收

### Path A：第一次使用

```text
首页
→ 开始测试
→ 7 题
→ 黄州结果
→ 阅读真实故事
→ 阅读诗词
→ 今日小行动
→ 生成分享卡
```

目标：全过程无死路、无强制注册、无额外说明页。

### Path B：第二次使用

```text
首页
→ 今日东坡
→ 读诗句
→ 看背景
→ 今日小行动
→ 生成今日东坡签
```

### Path C：主动探索

```text
首页
→ 苏轼人生宇宙
→ 浏览九站
→ 打开惠州
→ 阅读站点
→ 下一站儋州
```

### Path D：从结果继续探索

```text
测试结果
→ 查看这一站
→ 定位当前站点
→ 上一站/下一站
→ 返回宇宙
```

## 十七、V1 不做的交互

- 登录注册；
- 评论区；
- 用户排名；
- 社交关系；
- 无限滚动内容流；
- 复杂收藏夹；
- 长对话 AI 聊天；
- 实时地图；
- 复杂搜索；
- 3D 自由漫游。

---

## 十八、页面验收清单

```text
[ ] 首页第一屏只有一个最强 CTA
[ ] 用户 5 秒内理解产品是什么
[ ] 测试 30—60 秒可完成
[ ] 每道题可返回修改
[ ] 结果页第一屏立即揭晓站点
[ ] 史实、诗句、产品解读视觉分层
[ ] 今日小行动足够具体
[ ] 宇宙页九站可浏览
[ ] 当前测试站点可高亮
[ ] 分享卡可预览
[ ] 主要页面均有明确返回路径
[ ] 小屏幕无按钮遮挡和文字溢出
[ ] 无必须联网才能完成的核心路径
```

## 十九、设计落地优先级

```text
P0 首页
P0 测试流程
P0 结果页
P0 人生站点卡分享
P1 苏轼人生宇宙
P1 站点详情
P1 今日东坡
P1 今日东坡签
P2 最近结果
P2 轻量收藏/回看
```

比赛开发中若时间或平台限制导致范围收缩，必须优先保证全部 P0 完整，再实现 P1，禁止反向牺牲核心闭环去增加装饰性功能。

---

## 二十、最终交互判断标准

任何新增功能都先回答三个问题：

1. 它是否让用户更快进入苏轼的人生？
2. 它是否让真实诗词与当代生活连接得更自然？
3. 它是否增强“进入—理解—行动—分享”的核心闭环？

三个问题均是否定，则不应进入 V1。
