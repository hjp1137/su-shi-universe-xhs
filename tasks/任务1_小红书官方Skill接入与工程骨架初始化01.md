# 任务1 小红书官方 Skill 接入与工程骨架初始化 0.1

> 项目：苏轼宇宙小红书小工具  
> 阶段：Foundation  
> 前置任务：无  
> 任务优先级：P0

## 一、任务目标

在不预设普通 Web 工程方案的前提下，先接入小红书官方 `minitool-zip-builder-1.6.0.skill`，完整阅读其 `SKILL.md`，提取当前比赛小工具的硬性工程约束，并据此建立一个“可运行、可校验、可继续迭代”的最小工程骨架。

本任务的核心不是做业务页面，而是先回答：**这个项目应该以什么目录、入口、资源组织、运行方式和打包方式存在，才符合小红书官方要求。**

## 二、必须先阅读的文档

1. `docs/01_苏轼宇宙小红书小工具总体设计方案.md`
2. `docs/03_产品信息架构与页面交互设计.md`
3. `docs/04_视觉设计规范.md`
4. `docs/05_小红书小工具技术架构与工程规范.md`
5. 小红书官方 `SKILL.md`

如官方 Skill 与仓库既有设计文档存在冲突，以官方最新 Skill 为工程执行最高约束，并在成果说明中列出冲突点及建议修订项。

## 三、实施要求

### 3.1 获取并安装官方 Skill

从官方地址获取：

`https://fe-static.xhscdn.com/mini-tool/20260831163932/minitool-zip-builder-1.6.0.skill`

按实际 AI Coding 工具放入正确目录：

- Cursor / Claude Code：`.claude/`
- Codex：`.codex/`
- 其他：`.skill/`

禁止只下载不阅读；必须实际读取 `SKILL.md` 全文。

### 3.2 形成官方规则摘要

至少提炼并记录：

- 工程入口要求；
- 允许/禁止的文件与资源形式；
- HTML/CSS/JS 或其他运行约束；
- 本地静态资源规则；
- 网络请求限制；
- 包体或目录限制（若官方有）；
- 平台 API 使用方式；
- 校验命令/脚本；
- 打包要求；
- 最终产物要求；
- 常见错误与阻塞项。

在仓库中新建：

`docs/07_小红书官方Skill工程约束摘要.md`

该文件只总结官方 Skill 已明确支持的内容，不凭经验补充不存在的规则。

### 3.3 初始化最小工程

基于官方 Skill 建立最小运行骨架，至少保证：

```text
项目根目录
├── 官方 Skill 目录
├── 应用入口
├── src/ 或官方要求的源码目录
├── assets/ 或官方允许的本地资源目录
├── data/ 或后续可承载静态数据的目录
├── docs/
└── tasks/
```

具体目录名以官方 Skill 为准，不得为了符合上面的示意而违反官方格式。

### 3.4 建立最小可运行页面

页面只需证明工程成立：

- 显示“苏轼宇宙”；
- 显示核心 Slogan：“遇到烦心事，先去东坡那里坐一会儿。”；
- 一个基础按钮；
- 一个本地静态资源；
- 基础移动端安全区与 viewport 处理。

本任务不实现正式首页视觉。

### 3.5 第一次官方校验

严格按 `SKILL.md` 对当前工程执行校验。

若失败：

1. 记录失败项；
2. 修复；
3. 重新执行；
4. 直到无阻塞性错误，或明确记录无法解决的官方环境限制。

不得跳过校验并声称任务完成。

## 四、非目标

本任务不做：

- 人生测试；
- 九大人生站点；
- 今日东坡；
- 分享卡；
- 正式视觉特效；
- 后端；
- AI 对话；
- MySQL / Neo4j / RAG。

## 五、验收标准

### A. 官方 Skill

- 官方 Skill 已放入正确目录；
- 已实际读取 `SKILL.md`；
- `docs/07_小红书官方Skill工程约束摘要.md` 已生成；
- 摘要能追溯到 Skill，而非模型猜测。

### B. 工程

- 工程可按官方方式运行；
- 最小页面可正常打开；
- 无远程依赖才能显示的核心内容；
- 不存在明显不符合官方规则的工程结构。

### C. 校验

- 实际执行官方校验；
- 阻塞错误已修复；
- 留存校验摘要。

## 六、必须提交的成果

1. 官方 Skill 目录；
2. 最小工程骨架；
3. `docs/07_小红书官方Skill工程约束摘要.md`；
4. 必要的工程配置；
5. 本任务成果说明。

成果说明文件名必须包含任务序号，建议：

`tasks/results/20260907_任务1_小红书官方Skill接入与工程骨架初始化01成果说明.md`

成果说明必须列出：实际执行内容、修改文件、校验命令、校验结果、遗留问题、下一任务可直接使用的工程入口。

## 七、硬性约束

1. **禁止先按普通 Vite/React 项目经验搭建，再让官方 Skill 迁就工程。**
2. **禁止伪造官方规则。**
3. **禁止在未执行官方校验的情况下宣称验收通过。**
4. 如果官方要求和仓库文档冲突，先服从官方要求，再记录文档修订建议。
5. 本任务结束后，工程必须是后续所有业务任务唯一延续的基础。
