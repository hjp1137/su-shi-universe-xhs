# 任务11 小红书发布与分享传播闭环 0.1

> 项目：苏轼宇宙小红书小工具  
> 阶段：Competition Polish  
> 前置任务：任务1—10  
> 任务优先级：P0

## 一、任务目标

基于小红书官方小工具能力，打通“测试/浏览 → 分享卡 → 保存或发布 → 回流产品”的传播闭环。

本任务只使用官方 Skill 明确允许的能力。平台 API 名称、参数、权限、限制均以当前官方 `SKILL.md` 为准，禁止凭普通 Web 或旧版小程序经验猜测接口。

1. `docs/01_苏轼宇宙小红书小工具总体设计方案.md`

## 三、实施范围

### 3.1 平台能力适配层

建立独立平台适配层，页面不得到处直接调用平台 API。

至少抽象：

- 保存图片；
- 发布/分享（若官方支持）；
- 能力检测；
- 错误码映射；
- 用户取消；
- 不支持场景降级。

如果官方 Skill 不支持其中某项，必须明确记录并提供合理降级，不得虚构能力。

### 3.2 分享链路

目标流程：

```text
结果页 / 今日东坡 / 站点详情
↓
分享卡预览
↓
生成高清卡片
↓
保存图片或调用官方发布能力
↓
成功 / 取消 / 失败反馈
↓
返回产品
```

### 3.3 发布内容

若官方接口允许预填发布内容，应使用克制、自然的默认文案，用户仍可自行编辑。

示例方向：

- `原来我最近在苏轼的“黄州站”。`
- `今天抽到了一句东坡：莫听穿林打叶声。`
- `遇到烦心事，去东坡那里坐了一会儿。`

不得自动发布，不得绕过用户确认。

### 3.4 回流标识

在分享卡和允许的分享文案中保留清晰产品标识：

- 苏轼宇宙；
- `你的人生正在东坡哪一站？`；
- 核心 Slogan 的适度使用。

不堆二维码、外链或官方不允许的引流元素。

## 四、异常与降级

必须覆盖：

1. 用户拒绝权限；
2. 用户取消保存；
3. 用户取消发布；
4. 平台 API 不可用；
5. 生成文件不存在；
6. 分享卡生成失败；
7. 平台返回错误码；
8. 当前环境只支持保存、不支持发布。

任何失败都不得让用户卡死在 Loading。

## 五、埋点/本地事件（若官方规则允许）

至少在本地事件层定义：

- share_preview_open；
- share_card_generated；
- save_start / save_success / save_fail；
- publish_start / publish_success / publish_cancel / publish_fail。

如果比赛环境不允许外部分析服务，只保留本地事件抽象，不强行联网。

## 六、验收标准

- 平台能力调用集中在适配层；
- 官方支持的保存/发布链路可真实执行；
- 不支持的能力有明确降级；
- 用户取消不会被当成错误轰炸；
- 发布前必须由用户主动触发；
- 分享卡与最终发布素材一致；
- 返回工具后状态稳定；
- 无未经允许的网络请求；
- 再次执行官方阶段性校验无阻塞问题。

## 八、硬性约束

1. 绝不自动发布用户内容。
2. 绝不伪造小红书不存在的接口。
3. 绝不为分享功能绕开官方 Skill 网络限制。
4. 用户取消属于正常分支，不应弹出恐吓式错误。
5. 分享传播必须建立在用户主动行为和优质内容之上。
