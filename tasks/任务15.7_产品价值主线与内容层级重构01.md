# 一、产品北极星

本项目的核心价值统一定义为：

> ## **借苏轼的人生，找到此刻的自己。**

用户使用本工具后，必须明确获得三样东西：

1. **我现在更像苏轼人生中的哪一站？**
2. **苏轼在类似处境中，是怎样走过来的？**
3. **今天我能带走一句什么话、做一件什么小事？**

不得再把产品理解为“苏轼资料展示站”“九站内容目录”“诗词可视化合集”。

所有页面、入口、文案、层级都必须围绕上述三项用户收益服务。

# 二、核心产品对象：我的东坡答案

## 2.1 定义

新增并统一使用一个核心产品概念：

> ## **我的东坡答案**

用户完成东坡人生实验后，必须生成一个稳定、可复用的答案对象，至少包含：

```text
人生站点
一句东坡话
一句当下解释
今天的一件小事
```

示例：

```text
我的东坡答案

人生站点
黄州｜重新生活

一句东坡话
“莫听穿林打叶声，何妨吟啸且徐行。”

给此刻的你
不必等生活完全恢复正常，才允许自己重新开始。

今天的一件小事
出去走十分钟，不解决问题，只让自己慢下来。
```

## 2.2 数据要求

建议建立统一 ViewModel / 领域对象，例如：

```js
DongpoAnswer = {
  stationId,
  stationName,
  stationTheme,
  quote,
  quoteSource,
  insight,
  microAction,
  topTraits
}
```

要求：

- Result 页面使用它；
- `station_result` 分享卡使用它；
- 后续进入站点详情时可引用它；
- 不允许 Result、分享卡、站点详情分别重新拼接互相矛盾的文案；
- 继续保持“站点语义一致性”门禁。

# 六、Result：重构为“我的东坡答案”

## 6.1 页面职责

Result 不再承担完整站点详情。

它只负责：

> **告诉用户：我现在在哪一站，以及我今天能带走什么。**

## 6.2 第一屏信息结构

第一屏优先展示：

```text

黄州｜重新生活

“莫听穿林打叶声，何妨吟啸且徐行。”

不必等生活完全恢复正常，才允许自己重新开始。

今天的一件小事
出去走十分钟，让自己慢下来。
```

再提供两个明确动作：

- **生成我的东坡人生卡**（主动作）
- **进入黄州小宇宙**（次动作）

不得在第一屏塞入：

- 长历史；
- 多层史料说明；
- 作品目录；
- 大量标签；
- 与当前答案无关的入口。

## 6.3 内容层级

Result 的 L1 只有一个：

> **“我的东坡答案 / 黄州｜重新生活”**

诗句、解释、行动依次为 L2。

其他内容全部降级。

# 七、人生星河：从“九个站点目录”变成“苏轼完整人生地图”

## 7.1 页面唯一问题

人生星河应该回答：

> **苏轼的一生，到底经历了怎样的起伏？**

不再只是九个可点击节点的目录。

## 7.2 九站叙事标签

九站需要形成一条可理解的人生弧线，例如：

```text
眉山｜出发
京师｜被看见
密州｜豪情
乌台｜坠落
黄州｜重生
杭州｜把日子过好
惠州｜随遇而安
儋州｜极境从容
常州｜归途
```

具体词可依据现有正式站点数据校正，但必须：

- 一站一个清晰人生主题；
- 九站连起来像一条完整人生叙事；
- 用户无需点开也能看懂苏轼一生的起伏。

## 7.3 节点点击

点击节点后：

- 保留当前站点代表图；
- 只给一段极短预览；
- 明确“进入本站小宇宙”；
- 不在预览态塞完整正文。

3D / 星轨 / 粒子现有能力冻结，除必要层级调整外不要重新开发视觉系统。

# 十一、全站信息层级 L1 / L2 / L3 / L4

从本任务开始，全站统一采用四级内容层级：

| 层级 | 定义 | 示例 |
|---|---|---|
| L1 | 当前页面唯一核心结论/任务 | “你正在黄州｜重新生活” |
| L2 | 最重要的启发与动作 | 一句诗、一个解释、一个主CTA |
| L3 | 用户主动深入的内容 | 历史、作品、站点长卷、诗词星群 |
| L4 | 资料与注释 | 年代、出处、史料、版权、辅助说明 |

硬规则：

1. 一屏最多一个 L1；
2. L1 和 L2 不得被 L3/L4 抢夺视觉权重；
3. 第一屏不得同时出现多个同级主按钮；
4. 历史、出处、年代等不能一上来占主视觉中心；
5. 内容可以多，但必须按“答案 → 深入 → 资料”逐层展开。
