# 任务15.3 高质量视觉素材接入与诗词宇宙页面深度美化 0.1

> 项目：苏轼宇宙小红书小工具  
> 阶段：Visual 2.0 / Art Asset Integration  
> 前置任务：任务15、任务15.1、任务15.2已完成  
> 后续任务：任务16 视觉2.0与WebGL性能集中验收  
> 优先级：P0  
> 核心目标：将项目组统一提供的高质量“人生场景素材 + 宇宙视觉素材 + 重点诗词场景素材”正式接入现有Visual 2.0，使真实页面达到宣传效果图所体现的“现代水墨 × 深靛蓝 × 月色江水 × 东方诗词宇宙”完成度，同时保持Skill 1.6.0、Chrome 61、离线包体和性能基线不退化。

---

## 一、任务背景

任务15、15.1、15.2已经完成了视觉系统2.0、Three.js水墨宇宙特效和全站动效体系，但当前项目仍存在一个关键视觉缺口：

> 程序化背景、CSS、Three.js和卡片样式已经建立，但高质量“真实美术主视觉”不足，部分页面仍可能呈现“特效有了、画面却偏素”的观感。

项目组已经决定：

1. **主视觉美术素材由项目组统一生成并提供**；
2. Antigravity不得自行重新生成图片；
3. Antigravity只负责素材接入、裁切、压缩、轻微调色、遮罩、缩略图和页面构图；
4. Three.js负责“动起来”，图片负责“画面质感”，DOM负责“内容和交互”；
5. 本任务完成后，再执行任务16集中验收。

本任务不是重新设计Visual 2.0，而是把已确定的视觉方向真正落地到高质量素材层。

## 四、最高硬约束：禁止Antigravity自行生图

本任务明确规定：

### 允许

- WebP/JPG/PNG之间必要格式转换；
- 尺寸裁切；
- 压缩；
- 轻微亮度/对比度/饱和度调整；
- 添加深靛蓝渐变遮罩；
- 生成圆形/方形缩略图；
- 生成低清Fallback版本；
- 通过CSS `object-fit` / `background-position` 改变展示构图；
- 为性能制作一图多尺寸版本，但必须有明确必要性。

### 禁止

- 使用任何AI重新生成替代图；
- 擅自把统一风格换成另一种国风/赛博/卡通风格；
- 在图片中烘焙页面标题、按钮、诗词正文；
- 自行加水印、二维码、Logo文字；
- 为每个页面重复复制同一素材形成多个大文件；
- 把原始高清PNG全量打入最终ZIP。

原则：

> 图片是项目组提供的“正式美术资产”，不是开发阶段的临时占位图。

## 五、页面素材接入方案

### 5.1 首页：首页必须达到宣传效果图级别的第一视觉高潮

首页至少形成三层：

```text
底层：hero-home.webp / bg-cosmos-blue.webp
↓
增强层：Three.js月光、星点、薄雾、轻视差、星轨
↓
内容层：DOM标题、品牌文案、主CTA、今日东坡预览
```

要求：

- `hero-home.webp`作为首页真正主视觉，不再只靠CSS渐变；
- 保持标题和CTA可读，不允许图片细节压过文字；
- 建议在图片顶部/底部增加渐变蒙层而不是硬加不透明黑块；
- Three.js失败时，主图本身仍然足够漂亮；
- 首屏不能因图片未加载而延迟主CTA可用。

### 5.2 首页核心入口宇宙化

把核心世界观入口升级为“星球 / 星云 / 星轨”视觉组件，但不是所有功能按钮都宇宙化。

#### 一级入口

- 测一测 → `planet-entry-primary.webp`
- 逛一逛 → `planet-entry-secondary.webp` + 轨道/星轨
- 坐一会 → `nebula-entry-soft.webp` / 月雾型入口

可以叠加：

- `orbit-ring-glow.webp`
- `star-node-glow.webp`

必须保留清晰标题和文字提示，用户不能只看到一个“漂亮圆球”却不知道能点击。

#### 保持普通按钮形态

以下功能性操作不得强行改成星球：

- 返回；
- 上一题；
- 重新测试；
- 保存图片；
- 发布笔记；
- 取消；
- 关闭Modal。

### 5.3 测试页

测试页不需要每题一张大图，但应从“普通问卷”进一步升级为“人生场景选择”。

允许：

- 使用宇宙背景轻叠加；
- 当前题上方出现小型月相/星点/生命长河状态；
- 选中状态使用 `star-node-glow.webp` 或程序化光晕；
- 不得导致选项文字可读性下降。

### 5.4 测试结果页

结果页必须根据匹配站点使用对应的：

```text
station-<id>.webp
```

例如黄州：

```text
station-huangzhou.webp
```

必须形成：

```text
站点主视觉
↓
站点名称 / 年代 / 地点
↓
核心诗句
↓
真实经历
↓
东坡式理解
↓
今日小行动
↓
分享卡
```

其中黄州结果页作为第二视觉高潮，必须重点打磨。

### 5.5 东坡人生宇宙

这是本任务最重要的素材整合页之一。

要求：

- 继续保留任务15.1完成的Three.js/生命长河架构；
- 使用 `universe-path-glow.webp` 作为Fallback/辅助生命轨迹纹理；
- 九大站点使用对应 `station-*.webp` 作为“人生星球”内部图像纹理或圆形裁切缩略图；
- 当前节点使用 `star-node-glow.webp` 聚焦；
- 星球外圈可使用 `orbit-ring-glow.webp`；
- 节点间可以有星轨/江流，但不得变成西式科幻星图；
- 乌台→黄州的视觉转折必须最明显；
- 不为九站单独复制第二套相同大图。

目标：

> 用户不是在浏览九张卡片，而是在沿一条星河走完苏轼的一生。

### 5.6 站点详情页

每个站点详情页顶部必须使用对应站点图作为Hero视觉。

建议：

- Hero图高度适度；
- 文字区域叠加渐变；
- 重点站点可以做轻微视差；
- 下方史实卡、诗词卡继续用DOM；
- 不要把整页都铺成背景图导致长文阅读疲劳。

### 5.7 重点诗词作品页

五篇重点作品必须在素材到位后形成明显不同于普通长文页的视觉结构。

#### 《定风波》

- `poem-dingfengbo.webp`
- 风雨、徐行、从容
- 可配低频雨丝动效，但不能挡正文

#### 《念奴娇·赤壁怀古》

- `poem-niannujiao-chibi.webp`
- 赤壁、江月、山河、历史纵深

#### 《水调歌头》

- `poem-shuidiaogetou.webp`
- 中秋、明月、思念、旷达

#### 《题西林壁》

- `poem-tixilinbi.webp`
- 庐山、多重视角、层峦云海
- 必须继续保持“离开黄州后·赴汝州途中游庐山所作”的时空表达

#### 《赤壁赋》

- `poem-chibifu.webp`
- 江、月、舟、宇宙感、人的渺小与精神开阔

作品页结构继续坚持：

```text
场景主视觉
→ 作品标题 / 时间 / 地点
→ 核心诗句
→ 苏轼当时发生了什么
→ 为什么在这里写出这句话
→ 诗词原文
→ 今天如何理解
```

禁止退回“原文—翻译—赏析”的普通教辅页面。

### 5.8 今日东坡

可组合：

```text
bg-moon-halo.webp
+
badge-moon.webp（如已提供）
+
ornament-stardust.webp（如已提供）
```

目标：

> 像每天抽到一张真正值得收藏的“东坡诗签”，而不是普通信息卡。

### 5.9 分享卡

分享卡应继续由Canvas生成，但可使用项目组提供的轻量装饰素材作为Canvas素材源。

要求：

- 禁止直接截图页面冒充分享卡；
- 保证不同人生站点有视觉差异；
- 素材加载失败时仍可以生成基础分享卡；
- 分享卡不能依赖WebGL截图；
- 保存/发布继续走XHSBridge，不改变原主链。

## 七、图片加载与性能策略

### 7.1 不允许一次性加载所有图片

推荐：

- 首页只加载首页主图和首屏必要宇宙素材；
- 九站图片进入人生宇宙前再加载；
- 作品图片进入对应作品页再加载；
- 分享卡装饰在需要生成卡片时加载。

### 7.2 图片Fallback

图片失败时：

- 不得白屏；
- 使用原有CSS/Three.js背景；
- 内容和按钮继续正常；
- 可记录调试日志但不要阻止用户操作。

### 7.3 包体纪律

完成后必须统计：

- 人生场景素材总大小；
- 宇宙素材总大小；
- 诗词专属素材总大小；
- 装饰素材总大小；
- Three.js代码大小；
- 最终ZIP大小；
- 最大10个资源。

原则：

```text
最终ZIP ≤ 10 MiB：官方硬门禁
最终ZIP ≤ 2 MiB：优先目标，但视觉素材引入后允许合理超过，必须解释
```

如接入全部素材后包体明显偏大，应优先：

1. 降WebP质量；
2. 减少分辨率；
3. 复用图片；
4. 删除未实际使用素材；
5. 仅在必须时保留多尺寸版本。

不得通过删除核心视觉素材让项目重新变“素”来满足2MiB。
