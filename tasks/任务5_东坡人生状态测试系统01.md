# 任务5 东坡人生状态测试系统 0.1

> 项目：苏轼宇宙小红书小工具  
> 阶段：Core Experience  
> 前置任务：任务1.1、任务2—4  
> 任务优先级：P0

## 一、任务目标

实现“你的人生正在苏轼哪一站？”测试流程。测试是文学化、生活化的人生状态匹配，不做心理疾病分类，不输出医学或心理诊断。

用户应能在约 30—60 秒内通过 5—8 道单屏问题得到一个有明显区分度的东坡人生结果。

## 三、测试设计

### 3.1 入口与节奏

- 从首页主 CTA 进入；
- 5—8 题；
- 单题单主视图；
- 每题 3—5 个选项；
- 点击后轻反馈并进入下一题；
- 显示轻量进度；
- 支持返回上一题；
- 可重新开始。

测试开始前只需短提示：

> 最近的你，像东坡人生里的哪一段路？

### 3.2 评分算法

基于任务2的 `moods` 与 `quiz` 数据实现多维加权评分。

要求：

- 每个选项可影响多个状态维度；
- 不采用单一选项硬映射结果；
- 分值计算可解释；
- 同分有稳定 tie-break；
- 相同答案得到相同结果；
- 核心计算完全本地；
- 不依赖随机数或远程 AI。

评分函数应接近纯函数，便于测试。

### 3.3 结果映射

至少支持 V1 八类状态，并输出稳定：

```text
result_id
mood_id
station_id
score_summary（可选）
```

## 四、Skill 1.6.0 工程要求

- 题目数据必须通过任务2的离线装载层消费，禁止运行时 `fetch` JSON；
- JS 必须 ES2017 / Chrome 61 可解析；
- 禁止 ES Module runtime；
- 事件通过 `addEventListener` / Pointer Events，禁止行内 onclick；
- 不接入外部统计/AI服务；
- 测试结果仅做轻量本地状态保存；
- 不采集姓名、手机号、医疗/心理诊断等敏感信息。

## 五、文案边界

禁止：

- “你有焦虑症”；
- “你是抑郁型人格”；
- “你的心理问题是……”；
- “苏轼能治愈你”。

允许：

- “最近有点焦虑”；
- “你似乎正处在需要慢一点的阶段”；
- “你的答案更接近东坡的黄州时刻”。

## 六、逻辑测试

至少覆盖：

1. 每种结果均可到达；
2. 不存在永远不可达结果；
3. 同样答案结果一致；
4. 空答案不能完成；
5. 返回修改后重新计算正确；
6. 重置后旧答案清空；
7. 数组顺序变化不改变语义；
8. tie-break 稳定；
9. 非法 option ID 可识别；
10. 数据引用缺失时不白屏。

## 七、体验要求

- 题目口语化；
- 选项有真实差异；
- 不存在明显“最正能量答案”；
- 不制造负面情绪；
- 选中反馈在低端真机也流畅；
- 小屏不横向溢出。

## 八、非目标

本任务不负责完整结果页、不生成分享卡、不调用 AI 解释结果。

## 九、验收标准

- 5—8 道题完整走通；
- 进度、返回、重置正确；
- 评分算法有测试；
- 8 类结果均可到达；
- 结果稳定且有区分度；
- 无诊断式表达；
- 完全离线；
- 无 fetch/XHR/ESM/内联事件；
- Chrome 61 可运行；
- 阶段 audit 无新增阻塞。

## 十一、硬性约束

1. 测试是文学化状态匹配，不是心理测评。
2. 核心算法必须本地可运行。
3. 不允许随机决定结果。
4. 不允许为了结果平均篡改用户答案。
5. 所有结果 ID 来自统一数据层。
6. 不得突破任务1.1的离线/CSP/ES2017基线。
