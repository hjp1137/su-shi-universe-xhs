## 一、验收复核发现的P0问题

当前 `js/card_canvas.js` 中：

```js
function renderStationResultCard(ctx, vm, width, height) {
  drawBackground(ctx, width, height);
  if (assets && assets.scene) {
    drawImageCover(ctx, assets.scene, 0, 0, width, 390, 150);
  }
}
```

而调用处实际为：

```js
renderStationResultCard(ctx, viewModel, CANVAS_WIDTH, CANVAS_HEIGHT, assets);
```

JavaScript 会忽略函数签名之外的额外实参，因此 `renderStationResultCard` 函数体中的 `assets` 并未获得调用处的局部变量，会产生 `ReferenceError: assets is not defined` 风险。

该问题会直接影响：

```text
结果页
→ 生成人生站点卡
→ Canvas真实渲染
→ 预览DataURL
→ 保存/发布
```

属于传播主链 P0，不允许带入后续视觉收口任务。

## 二、修复要求

### 2.1 修复函数签名

将：

```js
function renderStationResultCard(ctx, vm, width, height)
```

修改为：

```js
function renderStationResultCard(ctx, vm, width, height, assets)
```

并确认：

- `station_result` 能读取 `assets.scene`；
- `daily_sign` 继续正确接收 `assets`；
- `station_node` 继续正确接收 `assets`；
- 不引入新的全局 `assets` 变量作为旁路修补；
- 不删除现有图片加载失败后的程序化背景Fallback。

### 2.2 检查同类作用域问题

集中检查 `js/card_canvas.js` 新增的所有异步图片加载和绘制方法：

- `loadLocalImage`
- `loadLocalImages`
- `drawImageCover`
- `renderStationResultCard`
- `renderDailySignCard`
- `renderStationNodeCard`
- `CardCanvas.renderCard`

确认所有异步回调中的局部参数都通过函数参数显式传递，不依赖未声明变量或偶然的 `window` 全局属性。
