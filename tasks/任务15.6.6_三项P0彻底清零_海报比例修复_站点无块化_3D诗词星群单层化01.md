# 二、P0-A｜海报舞台比例彻底修复：真实3:4最大化，而不是假全屏容器

## 2.1 核心原则

分享卡页面必须遵守：

> **舞台尺寸服从海报比例，而不是海报服从舞台高度。**

禁止继续使用类似：

```css
height: calc(100vh - 130px);
object-fit: contain;
```

去制造“容器很高但海报很小”的假全屏。

## 2.2 正确尺寸算法

Canvas固定比例：

```text
width : height = 3 : 4
```

根据 viewport 可用宽高计算：

```text
availableWidth  = viewportWidth - minimalHorizontalMargins
availableHeight = viewportHeight - nativeSafeArea - minimalTabs - minimalActions

posterWidth  = min(availableWidth, availableHeight * 3 / 4)
posterHeight = posterWidth * 4 / 3
```

若高度是限制因素，则反算宽度；不得出现黑边/大空白。

### 390×844目标
- 海报自身真实显示区域必须接近 viewport 可用面积上限；
- 海报外框宽高比必须接近 3:4；
- `img.getBoundingClientRect()` 与实际内容区域基本一致；
- 禁止海报外层比真实图片多出 >24px 的上下空白总量。

### 320 / 375 / 390 / 430 / 480
全部按相同算法自适应，不能为390单点打补丁。

## 2.3 页面结构进一步极简
允许保留：
- 小红书原生顶部区域；
- 一组极薄卡型Tab；
- 发布/保存贴边微操作。

要求：
- Tab不得把海报压缩到半屏；
- 发布/保存不得占据独立列宽；
- 不允许海报下方出现无意义大空白；
- 页面背景只是氛围，不得形成第二层大容器。

## 2.4 WYSIWYG运行时硬门禁
必须在自动化/浏览器级测试中同时验证：

```text
Canvas DataURL
= 页面主<img>.src
= saveImageToPhotosAlbum 输入源
= postNote 输入源
```

另外新增**视觉比例门禁**：
- 页面主预览 `img` 的宽高比必须为 `0.75 ± 0.01`；
- 不能只测父容器高度；
- 记录 320 / 390 / 480 的真实 `img` boundingClientRect。

# 三、P0-B｜站点真正无块化：从“无边框列表”改成连续镜头人生长卷

## 3.1 禁止事项
站点正文区不允许继续以以下形式作为主要排版：
- 大块深色 `rgba()` 文本承托面板；
- 大面积 `backdrop-filter: blur(...)`；
- 每卷都有独立矩形背景；
- “卷标题 + 一块正文 + 下一卷标题 + 一块正文”的连续模块模式。

代码里是否存在 `overlay` 不是验收标准，最终以**肉眼观感**为准。

## 3.2 新结构：一条真正连续的“人生镜头轨”
站点页面必须形成连续视觉路径：

```text
Hero全景
  ↓
时间/地点沿金线进入画面
  ↓
史实文本附着在场景边缘/空区
  ↓
代表名句作为第二个全景镜头
  ↓
生活事件沿轨迹自然展开
  ↓
3D诗词宇宙直接嵌入长卷
  ↓
现代共鸣/今日行动轻量收束
```

要求用户滚动时看到的是**画面与叙事逐段推进**，不是“模块一个接一个”。

## 3.3 图片直出与排字规则
### 必须做到
- 图片作为视觉主体直接展示；
- 文字优先放在图片天然空区；
- 可使用 text-shadow / 1px描边 / 很窄的方向渐变；
- 可重新裁切 `object-position` 寻找安全区；
- 明暗文字根据tone切换；
- 高亮粒子必须避让正文。

### 禁止
- 肉眼可见的整块磨砂板；
- 大片黑灰半透明矩形；
- 4px以上大区域 blur 托字；
- 图片大面积整体压暗只为文字服务。

## 3.4 站点差异化
至少人工检查：
- 眉山
- 黄州
- 杭州
- 惠州
- 儋州

要求：
- 每站 Hero / 第二镜头 / 生活镜头至少在图片、文字位置、节奏上有差异；
- 不允许 9 个站点只是换数据复用同一纵向模板。

## 3.5 文本可读性
所有正文必须满足：
- 不落在月亮、白云、白墙、强水光、高亮粒子上；
- 浅背景使用深字，深背景使用浅字；
- 任何一屏不得出现“肉眼明显看不清”的文字；
- 不允许用大遮罩解决可读性。

# 四、P0-C｜3D诗词星群彻底单层化：WebGL模式只允许一套PoetryPlanet

## 4.1 架构硬约束
在 WebGL / Three.js 模式下：

> **PoetryPlanet 必须同时是视觉主体、运动主体、命中主体、标签主体。**

必须彻底禁止/移除旧二维主星群层：
- `.constellation-star-node`
- `.star-node-img`
- 旧 SVG 环形轨道
- 旧 `coreNode`
- 旧独立 bubble/card
- 任何覆盖在WebGL舞台上的固定作品星球图片

允许 DOM 只保留：
- 区域标题；
- 极轻量操作提示；
- 聚焦后附着式文字入口；
- “展开全部作品”目录入口（位于3D舞台之外）。

## 4.2 PoetryPlanet统一对象
每颗星定义为：

```text
PoetryPlanet : THREE.Group
  ├─ sphereMesh / sprite主体
  ├─ halo
  ├─ optional ring
  ├─ labelAnchor
  └─ hitTarget
```

统一由 Group 控制：
- position
- rotation
- scale
- opacity
- focus
- depth

手指拖动时，用户肉眼看到的**图片/纹理星球本体必须一起旋转**。

## 4.3 星球视觉必须取代“绿色光团”
不得再出现“绿色光球是移动主体、图片星球是静态装饰”的效果。

作品星本体可采用东方五类主题：
- 冷月白
- 烟雨青
- 暖金
- 赤壁红棕
- 山水墨青

可结合：
- 本地作品/站点缩略图纹理；
- 柔和云层；
- 金色环；
- 轻微日冕。

禁止：
- 荧光绿能量球作为主视觉；
- 西式霓虹科幻感；
- 系统Emoji。

## 4.4 拖拽旋转
要求：
- 整个球状星群坐标系旋转；
- 所有星球、光环、标签锚点同步；
- 近景星球变大、变亮；
- 远景缩小、变暗；
- 背面星标签隐藏；
- 松手可有轻惯性，但必须可控。

### 专项动态验收
自动脚本必须：
1. 记录拖拽前至少3颗星的屏幕坐标；
2. 拖拽120~300px；
3. 再记录同3颗**星球主体**坐标；
4. 断言星球主体发生空间位移；
5. 禁止只验证halo/光团移动。

## 4.5 点击聚焦：星球自己来到眼前，禁止弹框
点击任一作品星后：
1. 整个星群自动采用最短路径旋转；
2. 目标星来到中央偏上焦点；
3. 放大约 `1.8~2.3x`；
4. 目标星提亮；
5. 其他星后退、缩小、降亮度；
6. 作品名/体裁/一句短诗以**贴着星球的附着式文字**出现；
7. 只保留一个极小“入画 / 赏析”动作。

### 强制禁止
- 独立矩形说明卡；
- 150×150级别的“微胶囊大面板”；
- 底部悬浮大框；
- 旧微名片。

附着式信息建议总占地不超过：
- 宽度：舞台 40%；
- 高度：90px；
- 诗句：最多1行或2短行。

## 4.6 标签深度与防重叠
默认态：
- 同屏清晰标签建议不超过4~5个；
- 背面全部隐藏；
- 远景只显示星球，不显示标题；
- 目标焦点附近优先保留标签。

不得再出现10个作品名同时挤在一屏。
