# 任务10 东坡人生分享卡生成 0.1

> 项目：苏轼宇宙小红书小工具  
> 阶段：Competition Polish  
> 前置任务：任务1.1、任务2—9  
> 任务优先级：P0

## 一、任务目标

实现可保存、可发布、具有独立审美价值的“东坡人生分享卡”。分享卡不是附属截图，而是本项目传播闭环的核心产品。

V1 至少支持：

1. 人生站点卡；
2. 今日东坡签；
3. 人生节点卡。

正式技术路线固定为：

> **本地结构化数据 → Canvas 2D → 本地图片/data URI → 任务11 Native Bridge。**

## 三、实现原则

- 使用 Canvas 2D，不使用远程截图服务；
- 不依赖 WebGL；
- 不使用 `<a download>`；
- 不通过网络上传图片换 URL；
- 不把每个结果预制为整张固定图；
- 正式生成代码必须 ES2017 / Chrome 61 可解析；
- 不使用 ES Module runtime；
- 卡片核心背景/纹理全部本地化。

## 四、卡片类型

### 4.1 人生站点卡

至少包含：

- `我的苏轼宇宙`；
- 人生站点结果；
- 3 个关键词；
- 主诗句；
- 一句东坡式理解；
- 产品名/传播入口文案。

### 4.2 今日东坡签

至少包含：

- 今日日期；
- 今日诗句；
- 一句短理解；
- 今日关键词；
- `今日东坡` 标识。

### 4.3 人生节点卡

至少包含：

- 站点地点与阶段名；
- 时间；
- 代表诗句；
- 一句站点概括；
- 苏轼宇宙标识。

## 五、Canvas 工程要求

### 5.1 DPR

不得无上限使用设备 DPR。

卡片导出应在清晰度与内存之间取得平衡，建立显式 DPR 上限；重复生成后释放大 Canvas/图片引用。

### 5.2 文本

必须处理：

- 中文自动换行；
- 超长标题；
- 长诗句；
- 标点避头/避尾的基础策略；
- 字体回退；
- 不同系统字体宽度差；
- 最小可读字号。

不得通过无限缩小字号解决溢出。

### 5.3 图片

- 优先少量 WebP/SVG/程序化纹理；
- 图片加载失败必须有纯色/渐变降级；
- 不允许远程 URL；
- 卡片素材必须纳入正式 ZIP。

### 5.4 Base64

Base64 只作为短生命周期桥接数据。

- 单条解码后 >100 KiB 时必须关注体积与内存；
- >1 MiB 不得作为静态内嵌资源长期存在，应改为独立资源或优化生成链。

## 六、视觉要求

延续：

**现代水墨 × 深靛蓝 × 月色 × 江水 × 微星图 × 人间烟火。**

同时考虑小红书信息流：

- 缩略图仍能识别标题；
- 不堆文字；
- 诗句排版精致；
- 有明显留白；
- 脱离工具也能识别“苏轼宇宙”；
- 不做廉价人格测试海报风。

## 七、内容安全

- 原诗句准确；
- 引号只包原文；
- 产品解读不得伪装成苏轼原话；
- 不出现心理诊断；
- 不使用“治愈焦虑”等效果承诺。

## 八、生成流程

```text
Result / Daily / Station 数据
↓
ShareCardViewModel
↓
Canvas 2D 绘制
↓
实际预览
↓
输出本地图片数据
↓
交任务11 XHSBridge 处理保存/发布
```

任务10不直接把平台 API 写进各业务视图。

## 九、性能与包体

必须记录：

- 卡片模板 JS/CSS 大小；
- 新增背景/纹理资源大小；
- 连续生成 10 次后的稳定性；
- 当前 ZIP 大小变化。

项目仍以 ZIP ≤2 MiB 为推荐目标，绝对不得突破 10 MiB。

## 十、验收标准

- 三类卡片均可生成；
- 8 类测试结果均可生成站点卡；
- 今日东坡可生成今日签；
- 九大站点可生成节点卡；
- 长短文案均无越界/重叠；
- 字体失败有回退；
- 图片失败有降级；
- 连续生成无明显内存恶化；
- 不依赖网络；
- 不使用 `<a download>`；
- 无 ESM/Chrome 61 语法问题；
- 阶段 audit 无新增阻塞项。

6. V1 分享卡只走 Canvas 2D，不引入 WebGL。
