## 三、修复项A：最终包验证脚本

检查 `scripts/verify_final_package.py`。

已知风险：ZIP 不存在时如返回非空 tuple，主程序可能将其当作真值，导致错误退出码。

### 必须做到

- `verify_package()` 的所有分支返回类型统一；
- ZIP 不存在、结构错误、禁用API、超包体时必须退出码非0；
- 正常通过时退出码0；
- 为“ZIP不存在”增加明确自动测试；
- 不允许只改提示文字而不验证退出码。

### 验收

至少验证：

```text
ZIP存在且合规 → exit 0
ZIP不存在 → exit != 0
ZIP根无 index.html → exit != 0
ZIP超硬门禁（可用临时测试包模拟）→ exit != 0
```

## 五、修复项C：Native Bridge 真机证据闭环

当前 Mock 测试可以保留，但不得再把 Mock 成功等同于真机通过。

必须在真实小红书支持 MiniTool 的客户端环境中至少完成一次：

```text
打开工具
→ 生成分享卡
→ writeTempFile
→ postNote 调起发布
→ 主动取消并正常返回
→ 再次生成分享卡
→ saveImageToPhotosAlbum
→ 确认保存结果
```

### 必须记录

- 手机系统与版本；
- 小红书客户端版本；
- 测试日期；
- Bridge 是否存在；
- `writeTempFile` 结果；
- `postNote` 调起结果；
- 用户取消返回结果；
- `saveImageToPhotosAlbum` 结果；
- 如遇权限弹窗，记录权限链。

### 证据要求

截图/录屏必须是真实不同状态，不得使用同一图片复制后改文件名。

至少形成：

1. MiniTool真实打开；
2. 分享卡页面；
3. 小红书发布器已被调起；
4. 取消后正常回到工具；
5. 保存相册成功或系统相册中可见结果。

如果因平台资格、客户端灰度等原因无法真机执行，必须明确写“真机阻塞”，不能标记 PASS。
