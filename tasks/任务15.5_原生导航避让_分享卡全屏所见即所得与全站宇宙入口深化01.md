# 任务15.5 原生导航避让、分享卡全屏所见即所得与全站宇宙入口深化 0.1

> 项目：苏轼宇宙小红书小工具  
> 阶段：Visual 2.0 / Navigation & Share Experience Refinement  
> 前置任务：任务15、15.1、15.2、15.3、15.4已完成  
> 后续任务：任务16 视觉2.0与WebGL性能集中验收  
> 优先级：P0  
> 核心目标：解决小红书原生返回键与项目自定义返回键冲突；将分享卡预览重构为“全屏、所见即所得、图片参与Canvas绘制”的真正传播页；系统性把仍作为普通卡片/文本Chip存在的跨页面导航入口升级成可识别、可点击、具有东方诗词宇宙语义的星球、星云、星轨与星图节点。

---

## 一、任务背景

任务15.4完成后，核心视觉已经从“普通文化H5”明显提升为“东方诗词宇宙”，但真实体验仍存在三类结构性问题：

1. **顶部导航冲突**：项目当前在所有非首页逻辑视图左上角插入自定义返回键，而小红书MiniTool容器本身存在原生返回控件，两者会发生视觉与触控区域重叠；
2. **分享卡仍是工具式预览**：当前分享页仍采用“页面标题 + 三类Tab + 缩放预览 + 下方按钮”的结构，卡片被缩放在一个预览容器内，不能做到用户看到的就是最终保存/发布的卡片；Canvas分享卡本身又主要由渐变、文字和金线构成，没有充分使用项目现有高质量人生场景图、诗词图和宇宙装饰素材；
3. **宇宙化只完成了部分页面**：首页和人生宇宙已经明显宇宙化，但站点详情、作品详情、结果页、今日东坡等页面中的很多“去另一个内容页”的入口仍然是矩形卡片、文本Chip或普通次按钮，导致“宇宙世界观”在页面之间断裂。

本任务不是再次增加大量特效，而是统一**导航空间语义 + 分享传播体验 + 宇宙入口组件体系**。

# 三、子任务A：解决小红书原生返回键与项目返回键冲突

## 3.1 禁止继续在左上角放项目返回箭头

当前 `App Shell -> nav-left -> btn-back` 方案必须调整。

### P0规则

在MiniTool真实容器中：

- **左上角原生导航区域只属于小红书容器**；
- 项目自身不得再在该区域放置返回箭头、关闭按钮或可点击热区；
- 不允许简单把当前返回键向右移动10～20px后继续使用，这仍然会形成双返回语义；
- App Header可以保留标题，但左侧必须为空或纯装饰、不可点击；
- 不得遮挡小红书原生控件。

## 3.2 新增“东方宇宙底部导航坞 Cosmic Dock”

建立统一底部导航，承担一级世界切换功能。

### 一级入口固定为3项

```text
首页        人生星河        今日东坡
Home        Universe         Daily
```

### 视觉要求

不得做成普通App的白底TabBar。

应采用：

- 深靛蓝半透明悬浮底座；
- 微弱月光/星尘边缘；
- 当前项形成暖金或月白轨道高亮；
- 首页可用“归舟/宇宙印记”语义；
- 人生星河用星轨/星球语义；
- 今日东坡用月相/明月印语义；
- 图标可使用现有SVG/CSS/现有cosmos/decor资产，不新增在线依赖；
- 必须兼容Chrome 61，不依赖现代CSS唯一实现。

### 布局

必须正确使用：

```css
padding-bottom: var(--safe-area-inset-bottom, env(safe-area-inset-bottom, 0px));
```

或项目Skill已确认的等价双安全区写法。

底部导航不得与系统Home Indicator冲突。

## 3.3 二级页面内部返回策略

底部一级导航不能完全替代“回到上一层”。对于以下页面：

- result
- station
- work

提供一个**非左上角**的“上一程”入口。

推荐顺序：

1. 优先放在底部Cosmic Dock上方的轻量浮动文字/轨迹按钮，例如：`← 上一程`；
2. 或放在页面首屏内容内部、标题上方，距离顶部原生区域足够远；
3. 不得重新占用左上角系统返回区域。

### 页面模式表

| 逻辑视图 | 顶部项目返回键 | Cosmic Dock | 上一程 |
|---|---|---|---|
| home | 禁止 | 显示 | 无 |
| universe | 禁止 | 显示 | 可选 |
| daily | 禁止 | 显示 | 可选 |
| result | 禁止 | 显示 | 显示 |
| station | 禁止 | 显示 | 显示 |
| work | 禁止 | 显示 | 显示 |
| quiz | 禁止 | **隐藏Cosmic Dock，防止误切导致答题中断** | 使用测试页自己的“上一题/退出测试”逻辑 |
| share-card | 禁止 | **隐藏普通Cosmic Dock** | 使用分享页专属全屏操作模式 |

## 3.4 Router不重写

保留现有 `historyStack`、`Router.back()` 与视图路由机制。

本任务只改变：

- Back触发入口在哪里；
- 一级导航如何呈现；
- 哪些视图显示/隐藏Cosmic Dock。

不得破坏已有路由测试。

# 四、子任务B：分享卡页改成全屏“所见即所得”模式

## 4.1 当前结构必须废除

当前：

```text
页面标题
↓
三类Tab
↓
预览容器
  └ 缩小的分享图
↓
提示文字
↓
发布/保存/跳转按钮
```

不得继续作为最终形态。

## 4.2 新结构

share-card视图进入后应成为**专属全屏海报模式**：

```text
┌──────────────────┐
│                  │
│   最终分享卡本体  │
│   3:4真实成品预览  │
│                  │
│   所见 = 导出图    │
│                  │
└──────────────────┘

[站点卡] [东坡签] [节点卡]   ← 紧凑悬浮切换器

[保存到相册]   [发布到小红书] ← 固定底部操作区
```

### P0要求

- 移除`share-card`页面通用SectionHeader；
- 不把卡片再放进第二层`ink-card`或缩放Tab容器；
- 真实Canvas导出的DataURL图片本身就是预览内容；
- 图片应尽可能占满可用内容视口宽度，保持3:4，不得被二次缩放到看不清；
- 390×844设备上，卡片应成为页面最主要视觉对象；
- 320、375、390、430、480宽度均不得横向溢出；
- 如高度不足，优先让海报区可轻量纵向滚动，而不是把卡片缩到很小；
- 页面背景只能作为陪衬，不得与分享卡抢视觉。

## 4.3 卡片类型切换器

保留三类：

- 人生站点卡
- 今日东坡签
- 人生节点卡

但不得继续使用占据一整行高度、导致预览缩小的传统Tab。

推荐使用：

- 分享卡下方的紧凑月相/星点分段器；或
- 底部操作区上方的三枚小型宇宙节点。

切换后重新生成真实Canvas DataURL。

# 五、子任务C：三类Canvas分享卡必须真正加入图片

## 5.1 当前程序化纯背景不足

`card_canvas.js` 当前主要使用：

- 深靛蓝渐变；
- 径向月光；
- 金色边框；
- 文字；
- 印章。

任务完成后，三类卡片必须加入**真实本地视觉素材**，而不是只在HTML预览外围放图片。

## 5.2 必须实现本地图片预加载

建立Canvas安全图片加载方法，例如：

```text
loadLocalImage(path)
drawImageCover(...)
drawImageContain(...)
```

要求：

- 只读取本地包内资源；
- 无fetch；
- 无网络；
- 图片加载失败必须回退到现有程序化背景；
- 生成流程变为异步时不得破坏现有callback/Promise调用链；
- Canvas失败不得阻塞分享页。

## 5.3 三类卡片图片构图

### A. 人生站点结果卡

主图：对应站点 `station-*.webp`

推荐构图：

```text
上部约38%～45%：人生场景大图
中间：渐变过渡至深靛/宣纸内容区
站点名 + 关键词
核心名句
东坡式理解
今日关键词/小行动
底部品牌
```

黄州必须呈现明确“江月/重生”视觉，不能只是一张深蓝文字卡。

### B. 今日东坡签

优先使用：

- 当日诗词对应 `poem-*`；
- 若无专属诗词图，则使用归属站点图；
- `badge-moon.webp` 可作为月相徽记；
- 必要时叠加星尘装饰。

推荐：场景图作为上半部/淡化背景，诗签主体仍保留宣纸阅读感。

### C. 人生节点卡

主图：站点场景图。

可叠加：

- `ornament-golden-orbit.webp`
- `constellation-overlay.webp`
- `star-node-glow.webp`

形成“人生节点被星轨锁定”的传播视觉。

## 5.4 所见即所得硬门禁

最终保存/发布的数据必须和用户看到的预览是**同一个DataURL**。

禁止：

```text

↓
真正保存出来还是旧Canvas纯文字卡
```

自动化和人工验收必须同时验证预览与导出一致。
