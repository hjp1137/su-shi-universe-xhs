## 三、实施要求

### 3.1 应用壳层

建立统一 App Shell，至少处理：

- viewport；
- 顶部/底部安全区；
- 页面高度与滚动策略；
- 逻辑视图切换；
- 返回行为；
- 全局背景；
- 错误兜底；
- 本地状态入口。

安全区必须采用 Skill 1.6.0 双兼容写法：

```css
padding-top: var(--safe-area-inset-top, env(safe-area-inset-top, 0px));
padding-bottom: var(--safe-area-inset-bottom, env(safe-area-inset-bottom, 0px));
```

不得让各视图自行复制一套安全区逻辑。

### 3.2 逻辑视图与导航

V1 预留：

```text
home
quiz
result
universe
station
work
daily
share-card
```

这些是**同一离线 H5 内的逻辑视图/状态，不是传统小程序 Page 文件**。

优先实现轻量状态路由；不得为了路由引入大型框架。

若使用 hash，必须证明在目标容器与 ZIP 场景下稳定；不得依赖服务端路由。

### 3.3 JS 组织

正式运行代码采用 Classic Script + `window.SuShiUniverse` 命名空间协作。

禁止：

- `<script type="module">`；
- import/export 残留；
- 内联 `<script>`；
- `onclick=` 等行内事件；
- ES2018+ 未转译语法。

交互事件优先 `addEventListener` + Pointer Events。

### 3.4 Design Tokens

建立统一 Design Tokens，至少覆盖：

- 背景色；
- 主文字；
- 次文字；
- 月白高亮；
- 青绿/湖蓝辅助；
- 暖灯火点缀；
- 边框透明度；
- 卡片背景；
- 圆角；
- 阴影；
- 间距；
- 字号；
- 行高；
- 动效时长；
- z-index；
- safe-area。

### 3.5 基础 UI 模块

概念上至少提供：

- PageShell；
- SectionHeader；
- PrimaryButton；
- SecondaryButton；
- InkCard；
- QuoteBlock；
- Tag；
- ProgressBar；
- BackButton；
- LoadingState；
- EmptyState；
- ErrorState。

这里的“组件”不要求引入 React/Vue，可用模板函数、DOM 构建函数和 class/data-attribute 约定实现。

### 3.6 CSS Chrome 61 基线

关键布局不得唯一依赖：

- Flex gap；
- `aspect-ratio`；
- `clamp()`；
- `:has()`；
- 逻辑属性。

如使用现代特性做增强，必须有基线回退。

Flex gap 若保留增强，按 Skill 的真实 DOM 测量方案检测，不以 `@supports(gap)` 作为唯一判断。

### 3.7 全局视觉基线

严格贯彻：

**现代水墨 × 深靛蓝 × 月色 × 江水 × 微星图 × 人间烟火**。

实现优先级：

```text
CSS → SVG → Canvas 2D → 少量压缩 WebP
```

V1 不使用 WebGL 作为正式视觉依赖。

系统字体优先，不引入远程字体或大字体包。

### 3.8 可访问性与移动端

至少处理：

- 文本对比度；
- 足够点击区域；
- 安全区；
- 长文本；
- 小屏无横向滚动；
- Pointer Events；
- 减少动态降级（可用时）；
- 不使用强闪烁。

## 四、性能与包体门禁

任务3完成时必须记录：

- 当前产物目录大小；
- 当前 ZIP 大小；
- 新增图片总大小；
- 新增 JS/CSS 大小。

目标：

```text
ZIP 尽量 ≤2 MiB
绝对不得 >10 MiB
```

Foundation 阶段若已经明显超过 2 MiB，必须先收缩再进入任务4。

## 六、非目标

本任务不做正式首页、不做测试算法、不做完整结果页、不做九站生命线、不做分享卡最终视觉。

可以有 Demo 状态，但不得把 Demo 当正式业务页面交付。

## 七、验收标准

- 所有核心逻辑视图可在同一 H5 Shell 下切换；
- Design Tokens 集中管理；
- 基础 UI 模块可复用；
- 视觉符合 `04`；
- 无普通后台/模板 H5 观感；
- 移动端无明显溢出和安全区问题；
- 无 ESM/内联 JS/网络依赖；
- JS/CSS 满足 Chrome 61 基线；
- V1 无 WebGL 依赖；
- 目录/ZIP 的官方阶段性 audit 通过；
- 数据层、视图层、视觉层职责清晰。

## 九、硬性约束

1. 不允许重新引入未经证明必要的大型运行时依赖。
2. 不允许 ES Module runtime。
3. 不允许使用复杂 3D/WebGL 作为 V1 基础视觉。
4. 不允许页面各自定义一套颜色和间距。
5. 不允许牺牲文字可读性追求水墨效果。
6. 不允许关键 CSS 只在现代 Chrome 正常。
7. 任何与 Skill 冲突的实现必须在本任务内解决。
