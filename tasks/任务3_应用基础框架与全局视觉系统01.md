# 任务3 应用基础框架与全局视觉系统 0.1

> 项目：苏轼宇宙小红书小工具  
> 阶段：Foundation  
> 前置任务：任务1、任务2  
> 任务优先级：P0

## 一、任务目标

在已经通过官方 Skill 基础校验的工程上，建立全局应用框架、基础页面容器、导航状态、通用组件和统一视觉系统，使后续所有业务页面都在同一套设计语言与工程约束中开发。

本任务完成后，应达到 **Milestone A｜Foundation Ready** 的技术和视觉底座要求。

## 三、实施要求

### 3.1 应用壳层

建立统一的应用壳层，至少处理：

- 移动端 viewport；
- 顶部/底部安全区；
- 页面高度与滚动策略；
- 页面切换；
- 返回行为；
- 全局背景；
- 错误兜底；
- 本地状态入口。

不得让每个页面自行实现一套安全区和背景逻辑。

### 3.2 页面状态与导航

为 V1 预留以下页面/状态：

- Home：首页；
- Quiz：测试；
- Result：结果；
- Universe：人生宇宙；
- Station：站点详情；
- Daily：今日东坡；
- ShareCard：分享卡预览/生成。

具体是否使用路由库，以官方 Skill 和当前工程能力为准。若不适合引入路由库，应实现轻量状态路由，不得为了技术偏好增加不必要依赖。

### 3.3 Design Tokens

建立统一 Design Tokens，至少覆盖：

- 背景色；
- 主文字；
- 次文字；
- 月白高亮；
- 青绿/湖蓝辅助；
- 暖灯火点缀；
- 边框透明度；
- 卡片背景；
- 圆角；
- 阴影；
- 间距；
- 字号；
- 行高；
- 动效时长；
- z-index 层级。

禁止在大量组件内散落不同的硬编码颜色和间距。

### 3.4 基础组件

至少实现：

- `PageShell`；
- `SectionHeader`；
- `PrimaryButton`；
- `SecondaryButton`；
- `InkCard` / 内容卡片；
- `QuoteBlock`；
- `Tag` / 关键词；
- `ProgressBar`；
- `BackButton`；
- `LoadingState`；
- `EmptyState`；
- `ErrorState`。

组件命名可按实际技术栈调整，但职责必须清晰。

### 3.5 全局视觉基线

严格贯彻：

**现代水墨 × 深靛蓝 × 月色 × 江水 × 微星图 × 人间烟火**。

需要形成：

- 深靛蓝沉浸背景；
- 克制的水墨/雾层；
- 月白高亮信息；
- 少量青绿水色；
- 少量暖灯火；
- 足够留白；
- 国风但不“古装网页”；
- 文艺但不牺牲可读性。

### 3.6 可访问性与移动端

至少处理：

- 文本对比度；
- 点击区域足够大；
- 重要按钮不能过贴屏幕边缘；
- 长文本不溢出；
- 小屏设备不横向滚动；
- 减少动态偏好若环境支持，应提供动效降级；
- 不使用强闪烁。

## 四、Milestone A 验收门槛

任务1—3完成后，必须能够证明：

```text
官方 Skill 约束已明确
+ 工程骨架可运行
+ 本地数据底座成立
+ 数据校验成立
+ 全局视觉系统成立
+ 页面壳层成立
```

如果这些基础能力仍不稳定，不进入任务4。

## 五、非目标

本任务不做正式首页、不做测试算法、不做完整结果页、不做九站生命线、不做分享卡最终视觉。

可以有 Demo 组件页面，但不得把 Demo 当正式业务页面交付。

## 六、验收标准

- 所有核心页面可以在同一 App Shell 下切换；
- Design Tokens 已集中管理；
- 基础组件可复用；
- 视觉风格符合 `04` 文档；
- 不存在明显“普通后台/普通 H5 模板”观感；
- 移动端无明显溢出和安全区问题；
- 工程仍可通过官方 Skill 当前阶段校验；
- 数据层、页面层、视觉层职责没有混在一起。

## 八、硬性约束

1. 不允许为了视觉效果引入未经官方验证的大型依赖。
2. 不允许使用复杂 3D 作为基础视觉依赖。
3. 不允许页面各自定义一套颜色和间距。
4. 不允许牺牲文字可读性追求水墨效果。
5. 任何与官方 Skill 冲突的技术实现必须以官方要求为准。
