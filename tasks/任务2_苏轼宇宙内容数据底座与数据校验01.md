# 任务2 苏轼宇宙内容数据底座与数据校验 0.1

> 项目：苏轼宇宙小红书小工具  
> 阶段：Foundation  
> 前置任务：任务1  
> 任务优先级：P0

## 一、任务目标

建立 V1 所需的本地静态内容数据底座，使后续页面、测试、结果页、今日东坡和分享卡全部由结构化数据驱动，而不是把文案直接写死在组件中。

本任务要解决三个问题：

1. 苏轼人生站点、事件、作品、诗句、状态、测试题、今日东坡如何统一组织；
2. 数据之间如何建立稳定引用关系；
3. 如何在构建阶段发现缺字段、坏引用、重复 ID、未审核内容等问题。

## 三、实施范围

### 3.1 建立数据目录

在符合官方 Skill 的前提下建立本地数据目录，建议至少包含：

```text
data/
├── stations.json
├── events.json
├── works.json
├── quotes.json
├── moods.json
├── quiz.json
├── daily-dongpo.json
└── sources.json
```

若工程采用 TypeScript，也可增加对应类型定义，但 JSON 仍应保持可独立检查。

### 3.2 建立稳定 ID 体系

必须统一 ID 规则，例如：

- `station_huangzhou`
- `event_wutai_poetry_case`
- `work_dingfengbo_moting`
- `quote_dingfengbo_xuxing`
- `mood_anxious`
- `source_songshi_sushi`

要求：

- ID 全局稳定；
- 不依赖数组下标；
- 不用中文空格或随机 UUID 作为人工维护主键；
- 后续修改显示名称不影响引用。

### 3.3 九大人生站点数据

按设计文档建立 9 个核心站点：

1. 眉山｜少年出发
2. 京师｜一举成名
3. 密州｜人到中年
4. 乌台｜人生骤雨
5. 黄州｜重新生活
6. 杭州｜把日子过好
7. 惠州｜岭南烟火
8. 儋州｜天涯仍有书声
9. 常州｜归途与谢幕

每站至少包含：

- 稳定 ID；
- 名称；
- 时间范围；
- 年龄信息；
- 地点；
- 关键词；
- 简短史实；
- 事件引用；
- 作品引用；
- 诗句引用；
- 当代产品解读；
- 今日小行动；
- 来源引用；
- `review_status`。

### 3.4 人生状态与测试数据

建立 V1 的 8 类用户状态：

- 最近很焦虑；
- 工作不顺；
- 被别人误解；
- 想太多、容易内耗；
- 最近很累；
- 对未来迷茫；
- 最近很孤独；
- 日子很普通。

每种状态必须关联一个或多个候选人生站点，并定义可解释的评分维度。

测试题控制 5—8 题，单题选项需能够为多个状态维度加权，禁止简单使用“选 A 就是黄州、选 B 就是杭州”的单题硬映射。

### 3.5 今日东坡数据

首批至少建立 30 条 `daily-dongpo` 内容，每条包含：

- 日期映射或稳定序号；
- 诗句引用；
- 简短背景；
- 东坡式理解；
- 今日小行动；
- 关联站点；
- 审核状态。

同一诗句可在不同语境复用，但不得形成大量重复文案。

### 3.6 来源与审核字段

所有史实、作品、诗句必须具有来源引用能力。

至少支持：

```text
source_id
source_type
citation_text
publication_or_work
volume_or_section
url_or_note（可选）
review_status
review_note
```

数据层必须能区分：

- 古代原文；
- 历史事实；
- 文学解释；
- 产品当代解读；
- 今日行动。

## 四、数据校验

实现自动校验脚本或等效机制，至少检测：

1. JSON 可解析；
2. ID 不重复；
3. 必填字段不为空；
4. 外键引用存在；
5. `station_id` 等引用未悬空；
6. `review_status` 合法；
7. 未审核内容不能进入 production 数据集合；
8. 测试题权重字段合法；
9. 每个结果状态至少有一个可达结果；
10. 每个人生站点至少有关联作品或事件；
11. 今日东坡引用的诗句真实存在；
12. 诗句正文与作品引用一致。

校验失败应输出明确文件名、ID 和问题，不只返回 `false`。

## 五、非目标

本任务不负责：

- 页面设计；
- 首页实现；
- 分享卡绘制；
- AI 自动生成史料；
- 为了“填满数据”而编造未核实内容。

如果某些内容尚未核实，可以保留为 `draft`，但不得伪装成已审核数据。

## 六、验收标准

- 数据目录和数据模型已建立；
- 九大站点均有结构化记录；
- 8 类用户状态可参与评分；
- 测试题数据结构成立；
- 今日东坡至少有可用于开发的首批数据；
- 所有跨文件引用可被自动校验；
- 数据校验脚本可重复执行；
- 有明确的审核状态控制；
- 页面层无需硬编码站点核心内容。

## 七、必须提交的成果

1. 数据文件；
2. 数据类型定义（如适用）；
3. 数据校验脚本；
4. 数据校验执行结果；
5. 本任务成果说明。

建议成果说明：

`tasks/results/20260907_任务2_苏轼宇宙内容数据底座与数据校验01成果说明.md`

## 八、硬性约束

1. 不允许用页面组件代替数据层。
2. 不允许用数组下标作为长期引用 ID。
3. 不允许把现代产品文案标记成苏轼原话。
4. 未核实史实不得标记为 `approved`。
5. 后续任务应优先消费本任务数据，不另建平行数据源。
