## 四、第二步：静态合规扫描

### 4.1 CSP / Script

扫描并清除：

```text
<script>内联代码</script>
onclick/onchange/oninput 等行内事件
javascript: URI
type="module"
import
export
eval(
new Function(
iframe
object
WebAssembly
```

注意：字符串、文档、测试样例中的关键词不能机械误判为运行时代码；结论必须人工复核。

### 4.2 禁止网络与 Web API

扫描实际运行源码：

```text
fetch
XMLHttpRequest
WebSocket
EventSource
RTCPeerConnection
navigator.geolocation
clipboard
Worker
SharedWorker
ServiceWorker
DeviceMotionEvent
DeviceOrientationEvent
window.open
window.prompt
requestFullscreen
<a download>
```

发现真实调用必须删除或改为 Skill 允许的本地/Native Bridge 路线。

## 五、第三步：工程形态纠偏

### 5.1 最终产物必须是离线 H5

正式产物至少满足：

```text
index.html
css/
js/
data/（如已有）
assets/（如已有）
```

如果任务1使用了开发框架，可以保留开发期工具的前提是：

- 最终产物不依赖开发服务器；
- 最终产物无 ESM；
- 无 CSP 冲突；
- Chrome 61 可解析；
- 体积合理；
- 审计通过。

如果现有框架无法低成本满足这些条件，应在本任务中切换为 Vanilla H5/ES2017，而不是把风险推给后续任务。

### 5.2 推荐脚本组织

如果需要纠偏，优先采用：

```text
js/namespace.js
js/compatibility.js
js/store.js
js/router.js
js/bridge.js
js/app.js
```

通过：

```js
window.SuShiUniverse = window.SuShiUniverse || {};
```

组织多文件 Classic Script。

## 六、第四步：Chrome 61 / ES2017 兼容纠偏

### 6.1 JS

检查直接产物是否存在：

- `?.`；
- `??`；
- 其他 ES2018+ 未转译语法；
- Chrome 61 不支持且无局部降级的 API。

优先直接改写为 ES2017，不为了少量语法引入重型转译链。

### 6.2 CSS

检查关键布局是否唯一依赖：

- Flex `gap`；
- `aspect-ratio`；
- `clamp()`；
- `:has()`；
- 逻辑属性。

必须提供 Chrome 61 基线回退。

Flex gap 如保留增强，按 Skill 规则做真实 DOM 测量能力检测。

## 七、第五步：安全区与输入事件纠偏

统一安全区：

```css
padding-top: var(--safe-area-inset-top, env(safe-area-inset-top, 0px));
```
