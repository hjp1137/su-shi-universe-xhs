# 一、任务背景与问题判断

当前版本已经具备：

- 东方诗词宇宙基本视觉语言；
- 首页、人生星河、今日东坡、站点、作品、分享卡等完整业务链；
- Three.js / WebGL增强层；
- 本地高质量场景素材；
- Cosmic Dock与宇宙化跨页面入口；
- Canvas分享卡与保存/发布链路。

但从真实页面观感来看，仍存在一个根本问题：

> **页面虽然已经“宇宙化”，但核心页面仍有明显传统H5的信息堆叠感；视觉重心不够集中，第一屏缺少一眼抓人的主舞台，成品感与目标效果图仍有明显距离。**

本任务不是继续增加更多装饰，不是简单加星星、加发光、加卡片阴影，而是重构五个页面的**画面构图、首屏信息密度、主视觉中心和空间层级**。

目标从：

```text
传统H5页面
+ 宇宙装饰
+ 若干视觉卡片
```

升级为：

```text
每个核心页面本身就是一张“作品”
+ 每一屏都有明确视觉主角
+ 核心入口无需寻找
+ 页面之间保持统一的东方诗词宇宙世界观
```

# 三、全局视觉原则

## 3.1 第一屏必须有“主角”

首页、人生星河节点展开、今日东坡、站点页、分享卡页进入后，用户必须在无需寻找的情况下立刻看见该页面的核心视觉对象。

禁止：

- 首屏只有标题和说明，核心入口在第二屏；
- 先看到大段文字，再看到主视觉；
- 主视觉被多层卡片框、Tab框、预览框缩小；
- 页面看起来像后台工具、表单页、传统内容列表。

## 3.2 去“盒子化”，但不牺牲可读性

继续压缩无意义的矩形深色卡盒。

允许保留卡片的地方：

- 长文阅读；
- 史实内容；
- 操作状态；
- 明确的信息分组。

不应继续使用矩形卡片的地方：

- 页面主视觉；
- 跨页面入口；
- 诗词星群；
- 星河节点；
- 分享海报；
- 今日东坡主诗签。

## 3.3 宇宙元素必须服务内容

可使用：

- 星轨；
- 星球；
- 月相；
- 节点光晕；
- 星尘；
- 水墨云气；
- 江水/月色；
- 星群关系线；
- 金色轨迹线。

但禁止：

- 为了“宇宙感”无意义铺满粒子；
- 变成西式科幻游戏UI；
- 特效压过苏轼、诗词、山水、人生经历；
- 影响文本可读性和点击区域。

总体视觉继续坚持：

> **东方山水 × 深靛蓝夜色 × 月白 × 暖金 × 朱砂 × 诗词宇宙。**

# 四、子任务A：首页第一屏重新构图

## 4.1 当前问题

当前首页结构过于松散：

- Hero高度较大；
- 标题、Logo、说明、CTA、今日诗句等纵向占用过多；
- 三大宇宙星体入口被挤到首屏以下；
- 用户必须向下滚动才能看到核心入口。

这违背首页“第一屏即产品名片”的要求。

## 4.2 P0目标

以 **390×844** 作为主要视觉验收视口：

> **无需任何纵向滚动，必须同时看到首页核心主视觉、主CTA和三大宇宙星体入口。**

至少保证三大入口的：

- 星体主体；
- 中文名称；
- 基本点击区域；

全部处于第一屏可视区。

375×812同样应基本成立。

320宽度允许整体更紧凑，但不得把三大入口整体推到第二屏。

## 4.3 推荐结构

首页第一屏重构为：

```text
┌────────────────────┐
│ 水墨宇宙主视觉      │
│ Logo / 苏轼宇宙     │
│ 一句核心问题         │
│ [进入我的东坡时刻]   │
│                    │
│  ●      ◎      ◐   │
│ 测一测  人生星河 今日东坡│
│                    │
└────────────────────┘
      ↓ 下屏仅露一点内容
```

### 上半区

控制在首屏约55%～62%视觉高度：

- 大场景背景保留；
- Logo适当缩小；
- 标题与核心问题压缩垂直间距；
- 删除/合并重复说明文字；
- 主CTA必须明显但不能占据过高面积。

### 下半区

三大星体入口成为首屏正式组成部分，而不是“下一模块”。

要求：

- 横向并列；
- 星体视觉明显；
- 三个入口大小有主次但整体平衡；
- 每项只保留短标题与极短副文案；
- 不再使用独立大矩形卡盒包裹；
- 点击热区≥44px。

## 4.4 首页内容取舍

以下元素如造成首屏拥堵，应后移到第二屏：

- 上次测试结果；
- 品牌理念长文；
- 大段今日东坡预览；
- 解释性说明。

第一屏只服务：

> **品牌 + 情绪 + 主CTA + 三大入口。**

# 五、子任务B：人生星河节点点击升级为“打开一个节点宇宙”

## 5.1 当前问题

当前人生星河点击节点后：

- 下方出现抽屉；
- 上方主要是模糊化背景；
- 缺少该站点自己的视觉主角；
- 点击节点的结果更像“弹出信息面板”，而不是“打开该人生节点”。

## 5.2 P0目标

点击任意站点节点后，上半屏必须立刻切换为该节点的**代表图场景**。

用户应明确感受到：

> **我刚刚打开的是黄州 / 密州 / 惠州，而不是一个通用抽屉。**

## 5.3 新结构

建议升级为：

```text
人生星河
↓ 点击“黄州”

┌────────────────────┐
│ 黄州代表场景大图    │
│                    │
│ 黄州 · 重新生活     │
│ 江月 / 徐行 / 烟火  │
│ “也无风雨也无晴”    │
└────────────────────┘

╭──── 节点详情抽屉 ────╮
│ 时间 / 发生了什么     │
│ 代表作品星点          │
│ 一句话理解            │
│ [进入黄州站]          │
╰──────────────────────╯
```

### 代表图

优先使用：

`assets/images/scenes/station-*.webp`

要求：

- 图片清楚可见，不得被0.3以下透明度压暗；
- 可局部叠加深色渐变保证文字可读；
- 根据站点自动切换；
- 不允许所有节点共用一张通用星空图。

### 节点主题层

场景图上叠加：

- 站点名；
- 时间/地点；
- 2～3个关键词；
- 一句代表诗句或人生主题。

## 5.4 动效

允许使用：

- 点击节点后场景图淡入；
- 当前星点向外扩散一道轨道光；
- 抽屉随后上浮。

总动效应短而明确，不允许为了特效拖慢内容出现。

## 5.5 Fallback

WebGL不可用时：

- 节点图照常显示；
- 抽屉照常打开；
- 站点入口照常点击；
- 不依赖Three.js才能完成视觉逻辑。

# 六、子任务C：今日东坡重构为“每日自动生成的收藏级诗签”

## 6.1 当前问题

“今日东坡”本应是最有传播潜力的亮点之一，但当前页面：

- 主卡过小；
- 存在明显“待生成/缩放预览”感；
- 页面像一个卡片工具页；
- 用户进入后没有立即看到完整漂亮的每日诗签。

## 6.2 产品定位重新确认

“今日东坡”页面的第一主角不是文字介绍，也不是操作按钮，而是：

> **当天自动生成的一张完整、漂亮、可收藏、可保存、可发布的3:4诗签。**

## 6.3 P0目标

进入 `daily` 页面后：

1. 自动生成当天诗签；
2. 无需用户点击“生成”；
3. 诗签必须包含真实本地图片；
4. 诗签占据页面主要视觉面积；
5. 用户第一屏即可看清诗句、场景图和主要排版；
6. 不允许长期停留在“正在生成”或空白缩放框。

## 6.4 页面结构

推荐：

```text
今日东坡 · 九月八日

┌──────────────────┐
│                  │
│   3:4 今日诗签    │
│   场景图          │
│   今日诗句        │
│   一句话理解      │
│   今日一事        │
│                  │
└──────────────────┘

      ○ 去此诗所在站
      ○ 保存 / 分享
```

### 主卡尺寸

在390×844视口中：

- 诗签应成为首屏最大单体视觉对象；
- 建议占可用内容区约65%～78%；
- 不再包在传统大Tab、大卡片框、预览框中；
- 保持3:4构图完整。

## 6.5 加载态

Canvas异步生成期间：

- 先显示与最终卡同尺寸的精致骨架/模糊场景占位；
- 不改变页面结构；
- 图片加载完成后原位替换；
- 不能出现页面先很空、随后突然大幅跳动。

若Canvas失败：

- 使用静态场景 + DOM诗签Fallback；
- 页面仍必须像完整作品，而不是报错页。

## 6.6 每日确定性

同一天：

- 内容映射稳定；
- 诗签图片稳定；
- 刷新不随机跳另一首；
- 保存/分享结果与页面看到的一致。

# 七、子任务D：苏轼人生站点页从“内容罗列”升级为“一个站点的小宇宙”

## 7.1 当前问题

当前站点页虽有高质量内容，但整体仍表现为：

```text
标题
→ 一块内容
→ 一块内容
→ 一块内容
→ 作品列表
```

页面信息完整，但视觉上接近传统文化H5专题页，缺乏“进入了苏轼某个人生宇宙”的独特体验。

## 7.2 新定位

每个站点页都应被视为：

> **苏轼一生中的一个独立小宇宙。**

黄州、密州、杭州、惠州不能只是换标题和文字，而要通过场景图、主题色、关键词、作品星群形成鲜明站点气质。

## 7.3 首屏：站点宇宙封面

站点页进入后第一屏应首先显示：

- 站点代表大图；
- 站点名称；
- 年代/地点；
- 一句人生主题；
- 2～4个关键词星点；
- 一首/一组代表作品入口。

推荐结构：

```text
← 上一程

[站点大场景]
      ◌ 星轨
   黄州 · 重新生活
  江月 · 徐行 · 烟火
“也无风雨也无晴”

      ↓ 向下进入站点长卷
```

## 7.4 中段：从卡片堆改成“人生长卷”

内容按叙事节奏重新组织：

### 第一章：东坡为什么来到这里

- 时间；
- 官职/处境；
- 发生了什么。

采用：

- 时间轨迹；
- 细金线；
- 小型星点；
- 一块主要文本区。

不要三个同尺寸矩形卡片并排/堆叠。

### 第二章：他在这里怎样生活

强化具体生活感：

- 日常；
- 交友；
- 饮食；
- 行走；
- 创作。

可形成“星轨上的人生片段”，视觉上左右错落，而不是统一卡片列表。

### 第三章：本站代表作品星群

继续使用任务15.5形成的 Constellation Cluster，但加强主次：

- 核心代表作作为主星；
- 次要作品为小星点；
- 星点之间可有轻微轨迹关系；
- 每个作品保留清晰文字；
- 点击进入作品详情。

### 第四章：如果你也在这一站

用更有情绪张力的“东坡寄语”收束：

- 一句现代共鸣；
- 一个今日行动；
- 一个分享入口。

让页面从历史重新回到用户自己。

## 7.5 视觉要求

允许站点不同主题轻微变化，例如：

- 黄州：江月 / 深蓝 / 暖金；
- 密州：旷野 / 风 / 月白；
- 杭州：湖水 / 青绿 / 月色；
- 惠州：岭南 / 暖雾 / 青绿金；

但全站必须保持同一设计系统，不得每站像不同项目。

# 八、子任务E：卡片预览页升级为“全屏海报舞台 + 右侧悬浮工具条”

## 8.1 当前问题

任务15.5虽然已经提出“全屏所见即所得”，但实际页面仍存在：

- 卡片缩放于明显的Tab/框架区域；
- 周围工具UI视觉权重过高；
- 海报本体没有真正成为页面绝对主角；
- 操作按钮仍占用较大底部空间；
- 画面张力不足。

## 8.2 P0目标

进入 `share-card` 页面后：

> **整页看起来首先是一张海报，而不是一个海报生成工具。**

海报本体直接占据主舞台。

## 8.3 新结构

推荐：

```text
┌────────────────────┐
│ ←                  │
│                    │
│  ┌──────────────┐  ○ 发布
│  │              │  ○ 保存
│  │   3:4 海报    │  ○ 换卡
│  │              │  ○ 返回
│  │              │
│  └──────────────┘
│                    │
└────────────────────┘
```

### 海报本体

要求：

- 不再嵌套传统Tab框；
- 不再套第二层大 `ink-card`；
- 不再有明显“预览窗”边框；
- Canvas导出的真实DataURL就是画面主角；
- 尽量利用屏幕高度而不是把海报缩成小图；
- 背景只做弱化氛围。

### 右侧悬浮操作轨

将高频操作变成右侧小型竖排按钮：

1. 发布；
2. 保存；
3. 切换卡型；
4. 返回/上一程（如与页面顶部返回重复，可只保留一个）。

按钮视觉建议：

- 圆形或小胶囊；
- 40～48px触控尺寸；
- 图标 + 极短文字或图标配悬浮文字；
- 深靛半透明；
- 暖金/月白高亮；
- 不遮挡海报关键文字。

### 卡型切换

三类卡：

- 人生站点卡；
- 今日东坡签；
- 人生节点卡。

切换器可以折叠到右侧“换卡”按钮中，点击展开小型星点菜单。

不允许重新出现横跨整页的传统Tab条。

## 8.4 小屏规则

320～375px时：

- 右侧工具轨仍保留；
- 可缩小视觉尺寸但触控热区不得低于44px；
- 海报与工具轨不得重叠关键内容；
- 必要时让海报区域轻微纵向滚动；
- 不允许因为适配小屏重新把海报缩回旧版小预览状态。

## 8.5 所见即所得继续作为硬门禁

任务15.5.1已建立的规则继续保持：

```text
页面显示的DataURL
=
保存给saveImageToPhotosAlbum的DataURL
=
发布给postNote的DataURL
```

本任务只改变舞台布局，不允许重新出现“两张皮”。
