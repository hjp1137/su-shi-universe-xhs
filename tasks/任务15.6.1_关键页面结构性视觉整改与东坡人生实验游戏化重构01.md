# 一、任务性质与当前结论

任务15.6完成后，整体视觉方向已经明显改善，但真实手机截图显示仍有一批根本性问题没有关闭：

1. 首页Hero仍有明显“第二层大卡片/容器”感，主视觉没有真正铺满内容区；
2. 当前“人生问答”仍是传统心理测试/问卷结构，且缺少明确的中途退出方式；
3. 人生星河点击节点后，详情层定位按文档高度而非当前可视高度工作，导致首屏可能只看到整屏模糊背景，必须继续滚动才能看到抽屉；
4. 卡片预览仍然是“页面里放一张缩小海报”，没有形成全屏作品舞台；
5. 当前“换卡”悬浮按钮及巨大横向卡型切换层过重；
6. “← ← 上一程”等返程入口仍是传统Web控件语言，与宇宙视觉体系冲突；
7. 站点详情下半段依然是第一章、第二章、第三章、第四章连续矩形卡片堆叠；
8. “诗词星群”目前更接近标题/占位模块，没有真正实现作品星群；
9. Canvas卡片上半部有场景图，但下半部存在大片空白、字号偏小、构图上重下轻的问题；
10. 关键页面仍存在“背景是宇宙，前景还是普通H5组件”的割裂感。

因此：

> **任务15.6不得直接视为Visual 2.0最终PASS。任务15.6.1关闭前，不进入任务16。**

本任务不是“再加一点星星、光效、圆角、阴影”，而是修改页面结构、交互模型和视觉信息架构。

# 二、最高设计原则

本轮所有修改必须遵守以下原则：

## 2.1 页面本身就是宇宙，不是“宇宙背景上的H5”

禁止继续通过以下方式假装完成视觉升级：

- 普通矩形卡片换渐变；
- 普通按钮加发光；
- 普通Tab加圆角；
- 内容卡片后面加星点；
- 连续章节卡片仅更换左侧边框颜色。

必须优先重构：

- 页面构图；
- 信息层级；
- 场景与内容关系；
- 轨道/星体/星群作为导航和内容结构本身。

## 2.2 视觉主角必须唯一

每个关键页面必须有明确第一视觉中心：

- 首页：三大宇宙入口 + 核心Hero；
- 东坡人生实验：当前互动场景；
- 人生星河：生命轨道 + 当前人生节点；
- 今日东坡：当天3:4诗签；
- 站点详情：本站场景与诗词星群；
- 卡片预览：3:4 Canvas成品本身。

其他控件必须退居辅助层。

## 2.3 功能动作和跨页面导航区别设计

- 保存、发布、确认等功能动作：可以使用高识别度按钮/小型悬浮动作；
- 返回、进入站点、回到星河等空间导航：优先使用星轨、星门、星点、星群等宇宙资源语义；
- 不再大量使用普通大矩形导航卡。

# 三、P0-A：首页去“双层容器”并完成真正首屏舞台化

## 3.1 当前问题

当前首页视觉上像：

```text
页面背景
└── 一张带左右边距和圆角的大Hero卡片
    ├── 标题
    ├── 文案
    ├── 主CTA
    └── 三颗入口星体
```

形成明显“页面里又嵌了一层页面”的感觉。

## 3.2 必须整改

首页Hero改为真正的首屏场景层：

- 主背景贴满内容区左右边界，不再保留明显大卡片外框感；
- 不允许Hero只占约90%宽度并露出第二层背景；
- 背景图、人物、月亮、标题、CTA、三颗入口星体属于同一个视觉场景；
- 三颗入口星体必须在390×844主验收尺寸首屏内可见，无需滚动；
- 首屏不能因为强行塞入内容而显得拥挤；
- 通过减少重复标题、压缩说明文案、调整视觉层级解决，而不是简单整体缩小。

## 3.3 首页主次

首屏视觉优先级：

```text
第一层：苏轼宇宙场景 + 三颗入口星体
第二层：核心CTA「进入我的东坡时刻」
第三层：标题 / 一句引导
第四层：次要标签 / 产品说明
```

“今日东坡·一言一事”如果保留，必须明显弱化，不得再次形成一张大型信息卡与Hero竞争。

# 四、P0-B：将“人生问答”彻底重构为「东坡人生实验」七幕宇宙微游戏

这是本任务最重要的产品创新项之一。

## 4.1 名称与定位

正式页面名称建议统一为：

> **东坡人生实验**

推荐副标题：

> **七次宇宙选择，看看你正走到东坡人生的哪一站。**

不再把用户体验呈现为“心理测试”“答题”“问卷”。

## 4.2 必须移除传统答题感

前台不得继续以以下结构作为主交互：

```text
第1题 / 共7题
问题
A xxxx
B xxxx
C xxxx
D xxxx
```

可以保留后台原有评分模型，但用户看到的必须是一组可操作的宇宙情境。

## 4.3 七幕微游戏建议

七幕应控制在单幕约5～10秒可理解、可完成；不得做成复杂游戏关卡。

### 实验01｜星体靠近

场景：用户的“自我星体”位于中央，周围出现不同属性的星体/光源。  
操作：拖动自己的星体靠近一个目标，或保持原位。  
测量：依靠、独处、行动、观察等倾向。

### 实验02｜行星撞击

场景：一颗星体沿轨道靠近用户星体。  
操作：用户可选择拖动避开、改变轨道、迎面接近/撞击。  
测量：面对突发冲突或变化时的应对倾向。

### 实验03｜星体聚合

场景：三颗代表不同任务/目标的小星同时漂浮。  
操作：用户可把三颗全部合并、只合并两颗、或保持分散。  
测量：聚焦投入、多线并行、权衡取舍。

### 实验04｜星体分裂

场景：一颗较大的星体承受不断增强的压力/引力。  
操作：用户可将其拆分为多个小星、继续维持整体，或将部分释放出去。  
测量：承压、控制、释放、重构方式。

### 实验05｜引力选择

场景：用户星体同时被多个不同引力场吸引。  
操作：拖动/放手，让星体进入某个引力场，或停留在平衡区。  
测量：稳定、安全、成就、关系、自主等倾向。

### 实验06｜星轨穿越

场景：前方有星云、障碍或两条不同轨道。  
操作：绕行、直穿、等待窗口、选择另一条轨道。  
测量：谨慎、冒险、效率、耐心与坚持。

### 实验07｜漂流星救援

场景：一颗小星正在偏离轨道，而用户自己的目标星也在前方。  
操作：拖动引力牵引小星、继续前进或在两者之间折中。  
测量：责任、他人、自我目标之间的权衡。

> 实际实现允许根据现有评分维度微调七幕语义，但不得退回七道传统选择题。

## 4.4 交互要求

每幕必须满足：

- 单手可完成；
- 1～2秒能理解操作方式；
- 主要拖拽/碰撞目标热区足够大；
- 有明显但克制的轨迹、吸附、碰撞、聚合、分裂反馈；
- 操作完成后短暂停顿并自动进入下一幕；
- 动效不可拖沓；
- 不依赖设备高帧率才能完成；
- 不因一次拖拽失败卡死。

## 4.5 必须提供点击式Fallback

为了保证可用性与低性能设备兼容：

- 每个拖拽/碰撞玩法必须存在等价的点击完成路径；
- 触控事件失败时仍能继续；
- `prefers-reduced-motion` 或 Low/Fallback 模式下仍可完成全部七幕；
- 不能要求WebGL成功才可以测试；
- DOM/Canvas核心交互必须独立可用。

## 4.6 进度表达

不再突出“第X题/共7题”。

优先使用：

```text
● ● ◉ ○ ○ ○ ○
```

或七颗星的轨道进度。

可辅以：

> 宇宙实验 03 · 聚合

但不要恢复问卷式题号视觉。

## 4.7 必须允许中途退出

当前“一进入就必须做完”必须修复。

要求：

- 不能在小红书原生左上区域叠加自定义返回按钮；
- 在实验内容区提供清晰的宇宙化退出入口，例如“返航星门 / 离开实验”；
- 退出时回到上一合理页面，不强制完成七幕；
- 中途退出不得生成伪结果；
- 重新进入可以重新开始；如实现进度恢复，必须行为明确且有测试。

## 4.8 评分模型兼容

原则上保留当前结果页、人生站点映射和已验证的评分逻辑。

实现时需要建立：

```text
微游戏操作结果
→ 标准化 interaction outcome
→ 映射至既有评分维度/选项权重
→ 原有结果计算器
→ 人生站点结果
```

禁止把评分逻辑散落在动画代码中。

建议新增独立配置，例如：

```js
ExperimentScoring = {
  experiment_01: { ... },
  experiment_02: { ... }
}
```

必须能够单测。

# 五、P0-C：人生星河节点详情改为“当前视口内打开”

## 5.1 当前Bug

真实手机截图显示：点击某人生节点后，有时当前首屏全部变成模糊/压暗背景，详情抽屉实际位于当前视口下方，需要继续滚动才出现。

这是视口定位错误，不允许归类为“视觉偏差”。

## 5.2 正确行为

无论用户当前：

- 位于第1站；
- 位于中间第4/5站；
- 位于第9站；
- 页面滚动到任意位置；

点击节点后，详情必须**立即进入当前可见屏幕**。

推荐：

- 详情层占当前可用视口约55%～70%；
- 首屏立即可见代表图、站点名、关键词和核心CTA；
- 星河背景继续可见，但弱化；
- 不允许首屏只剩模糊背景。

## 5.3 实现要求

定位必须基于当前可视区域，而非整个document高度。

需要正确考虑：

- `window.innerHeight` / `visualViewport.height` 可用性；
- 小红书顶部原生导航占位；
- safe-area；
- 底部Cosmic Dock高度；
- 当前scrollTop；
- 软键盘/浏览器视口变化（如涉及）。

不得使用一个固定绝对top值只对某个截图尺寸成立。

# 六、P0-D：卡片预览彻底改成全屏作品舞台

## 6.1 当前问题

现在仍然是：

> “卡片预览页面里放一张缩小的卡片”

而不是：

> “整页就是这张作品”。

## 6.2 海报尺寸

除小红书原生顶部区域和必要安全区外：

- 3:4 Canvas海报必须以当前可用区域允许的最大等比尺寸展示；
- 目标宽度约为内容区88%～94%，具体以不裁切为准；
- 页面不得出现巨大的无意义上下空白；
- 不再给海报套一层厚重“预览器”外框；
- Canvas DataURL图片本身就是主视觉。

## 6.3 卡型切换

彻底删除当前独立“换卡”悬浮按钮和点击后遮挡海报的大型横向选择层。

三种卡型固定为：

```text
人生站点卡 | 今日东坡签 | 人生节点卡
```

采用轻量Tab / Segment直接切换。

布局原则：

- 可以放在海报上方或下方的固定区域；
- 如为了单手操作在顶部/底部均设计切换入口，必须保证不重复制造两套抢视觉的重型Tab；
- 三项始终可识别；
- 不得遮挡海报主体；
- 切换后重新生成对应Canvas并更新同一预览DataURL。

## 6.4 功能按钮

右侧悬浮只保留必要功能动作，优先：

- 发布；
- 保存。

不再保留：

- 换卡；
- 重复的返回按钮。

按钮必须：

- 比当前版本缩小约25%～35%；
- 使用项目统一线性/宇宙图标；
- 禁止系统emoji图标，例如 `📥`、`↩️`；
- 不与海报争夺视觉中心。

## 6.5 删除说明性废话

删除类似：

> “轻触右侧悬浮轨一键发布或保存 · 点击「换卡」流转形态”

UI应自解释，不应依赖这种教程式说明长期占据页面。

## 6.6 所见即所得硬门禁继续保留

不得破坏任务15.5/15.5.1已经建立的WYSIWYG规则：

```text
Canvas生成DataURL
= 页面实际预览DataURL
= 保存使用DataURL
= 发布使用DataURL
```

三者必须同源。

# 八、P0-F：站点详情彻底去连续H5卡片化

当前站点正文：

```text
第三章 大卡片

```

虽然颜色不同，但仍是传统H5章节堆叠。

内容可包含：

功能识别仍要清楚，但视觉优先级低于站点场景与作品内容。

## 8.4 “漫游人生星河”宇宙化

不得继续使用普通大矩形导航卡。

# 九、P0-G：真正实现“诗词星群”

这是当前站点页视觉完成度最低、但最具有项目辨识度的模块之一。

## 9.1 不得再只是标题占位

禁止：

```text
第三章 · 诗词星群 · 这一站的精神星宿
[大片空白]
```

## 9.2 目标结构

每个站点的代表作品必须形成实际可见的作品星群：

- 一颗或数颗主作品星；
- 次作品星；
- 星轨/连线；
- 中心精神母题或本站星核；
- 点击作品星可进入作品详情。

示意：

```text
             ✦ 主作品
          ／           ＼
     · 次作品        · 次作品
          ＼           ／
          本站精神星核
          ／           ＼
     · 次作品        · 次作品
```

## 9.3 数据要求

# 十二、东坡人生实验技术实现约束

## 12.1 不引入重型游戏引擎

本任务不允许为了七个微游戏新增大型游戏框架。

优先复用：

- DOM/CSS transform；
- Pointer/Touch事件；
- Canvas 2D；
- 项目已有Three.js增强层（仅必要时）。

核心玩法不得依赖Three.js/WebGL才能完成。

## 12.2 事件兼容

考虑Chrome 61 / 小红书MiniTool环境：

- 不依赖仅现代浏览器支持的新语法；
- 触控事件必须有兼容实现；
- 多次快速触控不能重复结算；
- 进入下一幕前锁定结果；
- 页面销毁时清理事件、定时器、RAF。

## 12.3 动效预算

微游戏目标是“轻、快、准”，不是物理模拟器。

- 碰撞不需要真实刚体物理；
- 合并可以使用吸附+缩放+粒子；
- 分裂可以使用缩放+位移+淡入；
- 引力可以用轨迹插值模拟；
- 轨道穿越可用简单碰撞区域；
- 禁止引入高成本实时物理库。
