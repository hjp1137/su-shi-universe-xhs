# 任务15.1 Three.js水墨宇宙特效系统 0.1

> 项目：苏轼宇宙小红书小工具  
> 阶段：Visual 2.0 / WebGL Enhancement  
> 前置任务：任务15  
> 优先级：P0  
> 核心原则：Three.js只负责“宇宙感、空间感、氛围与镜头感”，DOM负责内容与操作；任何WebGL失败都不得影响核心功能。

## 一、任务目标

在严格遵守小红书 MiniTool Skill 1.6.0 的前提下，引入经过兼容验证的本地 Three.js/WebGL 渲染能力，为《苏轼宇宙》建立轻量级东方诗词宇宙特效系统。

本任务不是将产品3D游戏化，而是实现一种：

> **轻量 cinematic WebGL + 东方水墨氛围 + 诗词内容DOM叠层**

目标视觉包括：

- 月色；
- 远山空间；
- 江面与水光；
- 星点/墨点粒子；
- 薄雾；
- 轻微视差；
- 人生长河空间节点；
- 页面进入/结果揭晓的空间镜头感。

## 三、Three.js版本与集成方式

不得直接“安装最新版本后默认可用”。

执行AI必须：

1. 选择一个仍可满足项目WebGL 1兼容要求的Three.js版本；
2. 固定精确版本号；
3. 记录选择理由；
4. 验证最终构建代码能在Chrome61解析；
5. 最终Three.js运行时代码必须本地打包；
6. 若源码使用现代模块构建，最终产物必须转为项目允许的Classic Script/IIFE/UMD等离线形式，且最终ZIP中无运行时`import/export`。

如Three.js完整库体积影响明显，应评估：

- tree-shaking后的定制构建；
- 只保留实际使用模块；
- 或在必要时使用更小的纯WebGL实现。

不得为了“用了Three.js”而牺牲包体与兼容性。

## 四、WebGL架构

建议建立独立模块：

```text
js/effects/
├── webgl-engine.js
├── hero-scene.js
├── universe-scene.js
├── result-scene.js
├── quality-manager.js
└── fallback.js
```

具体目录可按现有工程适配，但必须保持：

```text
DOM内容层
↑
WebGL透明/背景层
↑
静态兜底层
```

### 核心接口建议

```text
Effects.init()
Effects.mount(sceneName, container)
Effects.setQuality(level)
Effects.pause()
Effects.resume()
Effects.destroy()
Effects.fallback()
```

场景切换时必须释放不再使用的几何体、材质、纹理和事件监听。

## 五、场景1：首页东方宇宙 Hero

实现一个低成本但有明显高级感的首页场景。

建议元素：

- 一轮低亮度月体；
- 2—3层远山剪影；
- 江面/水光平面；
- 极少量星点；
- 轻雾层；
- Pointer移动带来的极小视差；
- 页面静止时保持低频缓动。

不得：

- 大量高密度粒子；
- 实时重阴影；
- 复杂PBR材质；
- 大型模型；
- 动态反射；
- 多Pass后处理作为核心依赖。

首屏主标题和按钮必须由DOM完成，不得画进WebGL导致可访问性与点击问题。

## 六、场景2：东坡人生星河

这是Three.js最核心场景。

### 表现目标

用户滑动人生宇宙时，背景形成一条“人生长河/星河”。九大站点在空间中拥有不同氛围。

建议映射：

| 站点 | 特效倾向 |
|---|---|
| 眉山 | 青山晨雾、微光 |
| 京师 | 星光增强、暖金 |
| 密州 | 月体更明显 |
| 乌台 | 墨云、雨线、明度下降 |
| 黄州 | 江月、水光、暗转明 |
| 杭州 | 湖面波光、细雨 |
| 惠州 | 暖色粒子/灯火 |
| 儋州 | 海天、远星 |
| 常州 | 粒子减少、江面归静 |

重要：不要为每站创建一个大型独立3D场景。优先复用同一场景，通过参数切换：

- 背景色；
- 雾强度；
- 粒子数量；
- 月光位置；
- 水面亮度；
- 站点光晕。

减少资源重复与场景切换成本。

## 七、场景3：测试结果揭晓

结果页进入时可实现短时“节点汇聚”效果：

```text
暗场
↓
粒子/水光向某人生节点聚拢
↓
节点名称出现
↓
DOM结果内容进入
```

动画应短而克制，建议0.8—1.5秒级，不得阻止用户立即阅读或操作。

不同心境可通过色调/雾/光感变化，但不得做成“心理诊断颜色编码”。

## 八、性能预算

严格采用Skill给出的保守预算。

### 默认档

- drawing buffer DPR：`min(devicePixelRatio, 1.5)`；
- drawing buffer总像素约≤200万；
- 单纹理边长≤2048；
- 估算纹理显存≤64 MiB；
- draw call≤100/帧；
- 三角形≤100k/帧；
- 目标：稳定30FPS，有实测余量才提高。

### 低档

- DPR=1；
- 像素约≤100万；
- 单纹理≤1024；
- 纹理显存≤32 MiB；
- draw call≤50；
- 三角形≤50k。

本项目实际特效应尽量远低于这些上限。

## 九、动态降级策略

必须实现，不得只写文档。

至少具备：

```text
High / Medium / Low / Fallback
```

可以从Medium或Low启动。

### 逐级关闭顺序建议

1. 降低DPR；
2. 降粒子数；
3. 降雾/透明叠加；
4. 关闭水面额外细节；
5. 减少动画频率；
6. 停止WebGL并切到Canvas2D/CSS静态背景。

不得根据机型名单硬编码；优先能力检测和实际帧耗时。

## 十、生命周期与容错

必须处理：

- `visibilitychange`：后台暂停RAF；
- 页面恢复：重置时间差；
- resize：重新计算画布但继续受像素预算；
- `webglcontextlost`：停止渲染、阻止死循环；
- `webglcontextrestored`：尝试安全恢复；
- 初始化失败：立即Fallback；
- shader失败：Fallback；
- 用户低性能设备：可永久切低档。

不得出现WebGL失败导致白屏。
