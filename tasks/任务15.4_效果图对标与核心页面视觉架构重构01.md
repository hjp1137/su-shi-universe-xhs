# 任务15.4 效果图对标与核心页面视觉架构重构 0.1

> 项目：苏轼宇宙小红书小工具  
> 阶段：Visual 2.0 / Concept-to-Product Reconstruction  
> 当前基线：任务15.3完成，Commit `096ae1b501db09061a6fef24190dee3c31d037d7`  
> 前置任务：任务15、15.1、15.2、15.3  
> 后续任务：任务16 视觉2.0与WebGL性能集中验收  
> 优先级：P0  
> 核心目标：不再以“旧卡片界面上叠加图片”的方式美化，而是以项目组已经确认的宣传效果图为视觉目标，对首页、结果页、人生宇宙、站点详情、重点诗词、今日东坡与分享卡进行一次真正的“视觉架构级重构”，让真实程序首次达到“现代水墨 × 深靛蓝 × 月色江水 × 东方诗词宇宙”的沉浸式完成度。

## 一、任务背景与本轮审核结论

任务15.3的**素材接入工作本身通过**：28张正式WebP资产已完整落库，`ArtAssets`映射、构建隔离、离线加载、自动测试均已完成。

但项目组视觉审核结论为：

> **任务15.3：素材接入 PASS；效果图对标 FAIL。当前真实程序与已确认的宣传效果图仍存在明显结构性差距，不允许直接进入任务16。**

根因不是缺素材，而是当前实现仍然沿用V1/V2早期的“卡片 + 列表 + 小缩略图”信息架构，只把高质量素材作为背景或小图加入。

当前代码中存在以下典型问题：

1. 首页主视觉 `hero-home.webp` 被压到约 `opacity: 0.38`，并叠加从 `0.82` 到 `0.98` 的深色遮罩，导致真正的美术主视觉被大幅削弱；
2. 首页三大宇宙入口仍然是普通 `InkCard`，星球只作为约52px的小图标嵌在卡片左侧，并没有形成“星球/星云就是入口本身”的空间构图；
3. 人生宇宙主结构仍是 `border-left` 的传统纵向时间线，节点约20px，站点图约50px，主体仍是文本卡片，而不是九颗人生星球组成的生命星河；
4. 结果页和站点详情的场景图只有约180px高、透明度约0.38；
5. 重点诗词作品页的专属场景图只有约160px高、透明度约0.35；
6. Three.js、图片与DOM虽然都存在，但三层在视觉构图上仍然相互独立，没有形成宣传效果图中的“场景图为主体、宇宙特效融入场景、UI漂浮于画面”的统一空间。

本任务必须解决以上结构问题。

## 三、本任务最高原则

### 3.1 不是继续“加图片”

禁止继续采用：

```text
原卡片布局
+ 一张低透明度背景图
+ 几个小宇宙图标
= 宣布视觉升级完成
```

本任务必须改变**页面视觉架构本身**。

### 3.2 图片必须成为主视觉，而不是背景噪声

核心页面的高质量场景图应该首先被用户看见，然后文字和功能叠加其上。

### 3.3 宇宙入口必须“就是星球/星云”

不能再把星球缩成卡片左侧小图标。

### 3.4 人生宇宙必须真正去“卡片时间线化”

九站主视图不再使用传统左侧竖线 + 右侧连续卡片作为主视觉结构。

### 3.5 不新增AI图片

继续遵守：Antigravity不得自行重新生图。只使用现有正式素材，可裁切、压缩、遮罩、轻微调色。

# 四、首页必须重构为“沉浸式宇宙首屏”

当前首页的问题是：Hero仍然像一个圆角卡片，图像透明度低；三大入口仍然是纵向卡片列表。

## 4.1 首屏结构

在390×844参考视口下：

- 首屏视觉区域建议占 **520–650px** 高；
- `hero-home.webp` 应成为全宽/近全宽主背景；
- 不得再用 `opacity: 0.38` 弱化主图；
- 图片本身建议保持视觉可见度约 **0.75–1.0**；
- 深色遮罩只允许用于标题、CTA所在区域，不得把整张图片压成暗纹理；
- 允许顶部与底部使用渐变遮罩，但中部山水、月亮、苏轼人物必须清晰可辨。

### 首屏内容层次

建议：

```text
顶部微型品牌/印章
       ↓
苏轼宇宙（大标题）
你的人生正在东坡哪一站？
       ↓
简短副文案
       ↓
主CTA：进入我的东坡时刻
       ↓
三颗宇宙入口星体
测一测 ｜ 逛一逛 ｜ 坐一会
```

标题、文案和按钮可以覆盖在场景图上，但必须通过渐变、局部暗化保证可读。

## 4.2 三大入口彻底取消“普通卡片”表达

禁止使用当前：

- `home-nav-card`
- `UI.createInkCard` 作为三大入口的主视觉外壳；
- 52px小星球 + 右侧长文本卡片。

改为真正的三颗宇宙入口：

- `测一测`：主星球；
- `逛一逛`：带光环次星球；
- `坐一会`：柔和星云/月雾。

推荐规格：

- 星球主体直径约 **78–104px**；
- 三入口可以横向、弧形或错落排布；
- 标题直接位于星体下方或覆盖在下半部；
- 简介最多1行或2行极短文字；
- 点击区域至少44px；
- 星体有轻微漂浮/呼吸/光环；
- 当前不能使用普通白/深色矩形卡片作为入口背景。

首页应该让用户一眼就看到“这是宇宙入口”。

# 五、结果页必须重构为“人生站点揭晓海报”

当前结果页把站点图限制在180px且高度暗化，仍像一张结果卡。

## 5.1 黄州等结果主视觉

- 结果页顶部主视觉高度建议 **300–380px**；
- 场景图可见度建议 **≥0.75**；
- “你正处于人生的 / 黄州时刻”直接覆盖在画面下半部；
- 当前站点名应成为一级视觉信息；
- 使用局部金色/月色光晕，而不是整个卡片加黄色边框；
- 场景图与背景不得明显割裂成“小卡片头图”。

## 5.2 结果页信息层级

宣传效果图要求的结构：

```text
大场景
↓
人生站点揭晓
↓
代表名句（高质感纸张/诗签卡）
↓
真实经历短叙事
↓
今日小行动
↓
继续漫游 / 生成分享卡
```

禁止连续出现多张视觉权重相同的普通深色卡片。

# 六、人生宇宙必须进行本轮最大重构

这是本任务最重要的页面。

当前：

```text
左侧一条2px竖线
+ 20px节点编号
+ 50px圆形缩略图
+ 右侧9张文字卡片
```

这个结构必须退出“主视觉层”。

## 6.1 新主结构：东坡人生星河

使用：

- `bg-cosmos-blue.webp` / `bg-cosmos-mist.webp`；
- `universe-path-glow.webp`；
- 9张 `station-*.webp`；
- `star-node-glow.webp`；
- Three.js轻粒子、月光、薄雾作为增强层。

形成一条**蜿蜒或S形的生命长河/星轨**。

九大站点必须表现为九颗“人生星球”：

- 普通节点直径建议 **72–96px**；
- 当前结果站点建议 **104–128px**；
- 黄州可作为全线视觉高潮之一；
- 每颗星球内部直接展示对应人生场景图；
- 站点名称和极短副标题围绕星球布局；
- 星球之间由光带/江河/星轨连通。

## 6.2 去卡片化

人生宇宙主页面不再默认展示九张大段文字卡。

用户点击星球后，才出现：

- 轻量浮层；或
- 底部信息卡；或
- 进入站点详情页。

主视图首先是“漫游地图”，不是“阅读列表”。

## 6.3 必须删除/停用旧主视觉结构

主视图不得再以以下规则作为核心：

```css
.universe-river-timeline { border-left: ... }
.universe-node-badge { width:20px; height:20px; }
.universe-station-thumb { width:50px; height:50px; }
```

可保留为Fallback或无WebGL/无增强模式，但不能是默认视觉版本。
