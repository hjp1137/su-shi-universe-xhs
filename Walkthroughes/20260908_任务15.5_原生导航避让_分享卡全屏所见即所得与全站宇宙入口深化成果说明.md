# 成果说明：任务 15.5 原生导航避让、分享卡全屏所见即所得与全站宇宙入口深化 0.1

## 一、任务背景与核心目标

在任务 15.4 完成视觉架构重构后，全站东方诗词宇宙氛围已初步建立，但在真机交互与视觉语义上仍存在三类结构性问题：
1. **顶部导航冲突**：此前在所有非首页页面左上角放置项目自定义返回键，与小红书 MiniTool 容器原生左上返回/关闭按钮发生严重的视觉与触控区域重叠；
2. **分享卡仍为工具式缩放预览**：原分享卡页面嵌套了“大标题 + 横向大 Tab + 缩放预览容器 + 底部按钮”，卡片被严重缩放且无法做到用户预览图即最终导出图；同时分享卡仅为程序化背景，未充分融入包内高质量场景与诗词美术图，并残留“长按保存”错误提示；
3. **宇宙化断裂**：站点详情、作品详情、今日东坡、结果页等深层页面中，许多跨页面导航仍为死板的矩形卡片、纯文本 Chip 或普通次按钮，导致“宇宙世界观”在页面跳转时割裂。

本次任务 15.5 全面闭环解决以上痛点：
- **原生导航避让**：彻底清空左上角 `nav-left`，项目绝不在该区域放置任何返回键或可点击热区；
- **东方宇宙底部导航坞 (Cosmic Dock)**：建立底部悬浮磨砂导航坞（首页、人生星河、今日东坡），quiz/share-card 依规隐藏，二级页面（result, station, work, share-card）首屏内部提供轻量“← 上一程”；
- **分享卡全屏所见即所得**：废除外层通用 SectionHeader 与传统大 Tab，卡片 3:4 比例全屏居中沉浸呈现，预览图直接使用 Canvas 导出的同一 DataURL；采用紧凑月相分段器；彻底清零“长按保存”错误文案；
- **三类分享卡 Canvas 图片融合**：人生站点卡融入对应 `station-*.webp` 场景大图（羽化过渡），今日东坡签融入 `poem-*.webp` 场景与 `badge-moon.webp`，人生节点卡融入站点图与金色星轨 `orbit-ring-glow.webp`，加载失败平滑安全回退程序化背景；
- **全站跨页面导航入口宇宙化**：站点详情页收录诗词升级为“本站诗词星群 (Constellation Cluster)”、作品页所属站点升级为“微行星 Planet Portal”、今日东坡与结果页跨页面跳转升级为“站点微行星与星轨航道链接 Orbit Link”；功能按钮（保存/发布/重新测试）坚决保留标准高识别度按钮。

## 三、架构升级与技术设计对比

### 3.1 导航冲突原状与修复方式

- **冲突原状**：此前所有非首页逻辑视图激活时，`js/app.js` 会向 `nav-left` 动态注入 `<button class="btn-back">`，在小红书 App 中与容器原生左上返回/关闭按钮重合，导致点击穿透或双返回语义。
- **修复方案**：
  1. `app.js` 内部彻底移除任何创建或挂载 `.btn-back` 的逻辑，每次切页强制清空 `navLeftEl.removeChild`；
  2. `nav-bar-left` 维持透明占位，小红书左上角原生区域 100% 专属于容器；
  3. App Header 仅居中保留标题（如“苏轼宇宙”），右侧预留，左侧不放任何自定义按钮；
  4. 一级页面切换由底部悬浮“Cosmic Dock”承载，二级深层页面（result, station, work, share-card）首屏内容内部提供“← 上一程”文字轨迹按钮。

### 3.3 Share Card 旧结构 vs 新结构

- **旧结构**：
  `外层SectionHeader` → `横向大Tab (share-tabs-nav)` → `外层大卡片` → `缩小版预览图 (max-width: 320px, padding: 8px)` → `长按保存提示文字` → `纵向排列按钮`
- **新结构**：
  `share-card-top-nav (← 上一程)` → `share-card-poster-wrap (3:4 高清直出海报，直接绑定 Canvas DataURL)` → `share-type-segment (紧凑月相分段器：● 站点卡 / ◐ 今日签 / ○ 节点卡)` → `share-card-actions (高识别度标准功能按钮：一键发布到小红书 / 保存卡片至相册 / 漫游宇宙星轨)`

### 3.4 三类 Canvas 卡片本地图片构图与 DataURL 一致性证明

1. **人生站点卡 (Station Card)**：
   - 使用本地图片：`assets/images/scenes/station-*.webp`
   - 构图布局：Canvas 顶部 390px 区域（约 39% 高度）绘制站点场景大图，底部覆盖 150px 高度水墨渐变羽化至深靛蓝；下方舒朗排版站点名称、历史现场史实、现代生活启发与人生行动印记；
2. **今日东坡签 (Daily Card)**：
   - 使用本地图片：`assets/images/poems/poem-*.webp`（无则回退对应站点图）+ `assets/images/decor/badge-moon.webp`
   - 构图布局：顶部 350px 绘制诗词场景大图并羽化，右上角加盖月相明月印；正中悬浮米色宣纸质感诗笺与朱砂手泽印，下方呈现当代视角解读与今日一事；
3. **人生节点卡 (Node Card)**：
   - 使用本地图片：`assets/images/scenes/station-*.webp` + `assets/images/cosmos/orbit-ring-glow.webp`
   - 构图布局：顶部 380px 场景图叠加金色星轨微光与光晕，呈现“人生节点被星轨锁定”的传播视觉，下部清晰记录历史现场史料与生活启示；
4. **所见即所得硬闭环**：
   - 预览与导出直接使用同一个局部变量 `currentDataUrl`；
   - 用户在页面上看到的大图即为 `CardCanvas.renderCard` 生成的图像；
   - 点击“保存卡片至相册”直接将 `currentDataUrl` 传入 `Bridge.saveImage(currentDataUrl)`；
   - 点击“一键发布到小红书”直接将 `currentDataUrl` 传入 `Bridge.postNote({ dataUri: currentDataUrl, ... })`；
   - 绝对不存在“HTML 预览与 Canvas 导出两张皮”问题。
